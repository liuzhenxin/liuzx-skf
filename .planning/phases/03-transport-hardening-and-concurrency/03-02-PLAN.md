# Plan 03-02: Blocking FFI Isolation, Per-Provider Serialization, and Timeout

<objective>
把厂商 FFI 从 async 运行时 worker 上移开，用一个 provider 库一把全局锁串行化原生访问，并给非 wait 调用加 30 秒超时。三者必须同批落地（03-CONTEXT D-06），否则 `std` 锁会把 worker 线程卡在锁上。

**相对 D-07 的实现细化（必须记录为偏差）：** CONTEXT 选择"每调用点 `spawn_blocking`"，但守卫的 `Drop` 本身也执行阻塞 FFI（`dis_connect_dev`/`close_application`/`close_container`/`close_hash`）。若只在显式调用点包裹，守卫在 async worker 上 drop 时仍会阻塞 worker，TRANS-04 不成立。因此本计划改为**每个请求的处理体整体运行在阻塞池上**：显式调用与守卫析构都在同一阻塞线程，且天然串行。超时改为包裹 `JoinHandle`（"调用方止损"语义，与 D-08 一致）。锁、串行化、超时三者的语义与 CONTEXT 一致，仅隔离粒度由"每调用"变为"每请求"。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-03-05 | 并发使用同一厂商句柄导致进程级崩溃（RES-01 同类故障） | HIGH | `Arc<Mutex<()>>` 全局锁，所有 native 方法取锁；wait/cancel 显式豁免 |
| T-03-06 | 全局锁把 async worker 卡死，缓慢设备拖垮整个服务 | HIGH | 锁只在阻塞池线程上获取；处理体整体在 `spawn_blocking`；30s 超时让调用方止损 |
| T-03-07 | 锁住 wait 导致 cancel 死锁 | HIGH | `wait_for_event`/`cancel_wait_for_event` 不取锁、不超时 |
| T-03-08 | 为共享锁引入新的 `unsafe impl Send/Sync` | HIGH | 只用 `Arc<Mutex<()>>`（本身 Send+Sync）；`provider_invariants` 保持各一处 |
| T-03-09 | 超时后状态丢失或资源泄漏 | MEDIUM | 超时仅影响该连接；阻塞线程继续执行并最终 drop 真实状态释放资源 |
</threat_model>

<must_haves>
- `NativeSkfProvider` 持有 `Arc<std::sync::Mutex<()>>`，每个 native FFI 方法取锁；`wait_for_event`/`cancel_wait_for_event` 不取锁
- 每个请求的 dispatcher 处理体在 `tokio::task::spawn_blocking` 上执行；domain 处理器与 `handle_request` 为同步函数
- 非 wait/cancel 请求 30s 超时返回 `-1` + `Device operation timed out after 30s`
- `unittest`/不变量：仍恰好各一处 `unsafe impl Send`/`Sync`
- 缓慢 provider 调用（`SkfError::Blocking`）不阻塞 `SetLanguage` 这类无 token 请求
- `cargo test --test contract_fixtures` 37/37
</must_haves>

  </read_first>
  <action>
    1. 在 `src/provider/native.rs` 定义：
       ```rust
       /// Serialises access to the vendor library.
       ///
       /// The vendor DLL has no documented thread-safety guarantee, so every call
       /// through a guard takes this lock. WaitForDevEvent/CancelWaitForDevEvent
       /// deliberately do NOT take it: cancel must reach the library while wait is
       /// parked, or the pair deadlocks.
       type FfiGate = std::sync::Arc<std::sync::Mutex<()>>;
       fn gate_lock(gate: &FfiGate) -> std::sync::MutexGuard<'_, ()> {
           // Poison recovery: one panic must not permanently fail every later call.
           gate.lock().unwrap_or_else(|e| e.into_inner())
       }
       ```
    2. `NativeSkfProvider` 增加字段 `gate: FfiGate`；`new`/`from_api`/`from_config` 初始化为 `Arc::new(Mutex::new(()))`。
    3. `NativeDevice` / `NativeApplication` / `NativeContainer` / `NativeDigest` 各增加 `gate: FfiGate` 字段，创建时 clone 自 provider 或父守卫。
    4. 在每个进入 FFI 的 native 方法体开头插入 `let _gate = gate_lock(&self.gate);`——包括 `NativeDevice::state/lock/unlock/transmit/random/info/set_label/begin_digest/begin_digest_impl/open_application`、`NativeApplication::enum_containers/verify_pin/open_container/delete_container/create_container`、`NativeContainer::container_type/export_certificate/import_certificate/sign_ecc/sign_rsa/gen_ecc_key_pair/gen_rsa_key_pair/set_symm_key/encrypt/decrypt`、`NativeDigest::update/finalize`、provider 的 `enum_devices/device_state/open_device`。`Drop` 实现内同样取锁后再调用 close/disconnect（保证析构也串行）。
    5. **不要**给 `NativeSkfProvider::wait_for_event` 和 `cancel_wait_for_event` 加锁。
    6. 在 `tests/provider_invariants.rs` 增加一条结构断言：`src/provider/native.rs` 中 `wait_for_event`/`cancel_wait_for_event` 的实现块内不得出现 `gate_lock`（可用相邻行文本检查），并断言 `unsafe impl Send`/`Sync` 计数仍各为 1（既有测试已覆盖后者）。
  </action>

       - **回归要求**：`SetLanguage` 夹具在 replay 中会先设置语言再请求中文消息，语言状态必须跨请求保留；`contract_fixtures` 通过即是证据。

    6. `CancelWaitForDevEvent` 分支保持直接调用（现在运行在阻塞线程上）。
    7. 不改动 `server::Session` trait 签名。
  </action>

<task id="03-02-03" type="execute">
  <name>30 秒请求超时（wait/cancel 豁免）</name>
  <files>src/main.rs</files>
  <read_first>
    - 03-02-02 产出的 `JsonRpcSession::handle`
    - `.planning/phases/03-transport-hardening-and-concurrency/03-CONTEXT.md` — D-08/D-09/D-10/D-11/D-15

  <action>
    1. 新增常量 `const FFI_TIMEOUT: std::time::Duration = std::time::Duration::from_secs(30);` 与豁免判定函数：
       ```rust
       fn is_wait_method(method: &str) -> bool {
           matches!(method, "WaitForDevEvent" | "CancelWaitForDevEvent")
       }
       ```
       `handle` 需要先知道方法名：在 `JsonRpcSession::handle` 内先用 `serde_json::from_str::<RpcRequest>(text)` 解析（解析失败仍交给 dispatcher 返回 `-1 Invalid JSON`，或直接在此返回同样形状），取 `req.method`。
    2. 对非 wait 方法：`match tokio::time::timeout(FFI_TIMEOUT, task).await { Ok(joined) => ..., Err(_elapsed) => { log::warn!("request timed out after {:?}", FFI_TIMEOUT); self.guard.put_state(SessionState::new(self.ttl)); return format!("{{\"error\":-1,\"message\":\"Device operation timed out after 30s\"}}"); } }`
       —— 构造响应时必须带原请求 id。可直接构造 `RpcResponse::err(-1, "Device operation timed out after 30s".into(), req.id.clone())` 并序列化。
    3. 对 wait 方法：直接 `task.await`，不超时。
    4. 超时后阻塞任务仍在运行；其 `state` 会在任务结束时随线程 drop，从而释放资源。**不要**尝试 join 或取消该任务。占位状态 `SessionState::new(self.ttl)` 只为让该连接可继续响应（空授权/空句柄），不得复用原状态。
    5. 在 `handle` 顶部记录 `let request_id = serde_json::from_str::<RpcRequest>(text).ok().and_then(|r| r.id);` 用于超时响应。
  </action>
