# Plan 09-03: Audit End-to-End Proof and Regression

<objective>
用真实二进制证明授权拒绝会产生一条结构化、非敏感的审计日志行（AUD-01/02），并完成阶段 9 的回归（fmt/clippy/i686），确认审计与绑定策略改动未破坏既有行为。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-09-02 | 审计只在单元测试层面成立，运行时不发射 | HIGH | 真实服务 stderr 捕获断言 |

<must_haves>
- `tests/audit.rs` 启动真实服务（`RUST_LOG=info`），触发一次未授权操作，断言 stderr 出现含 `"audit":true` 与 `"authorization.denied"` 的行
- 断言捕获内容不含 `pin`/`token`/`PRIVATE KEY` 等敏感串
- `tests/log_redaction.rs` 仍绿（审计模块不引用敏感标识符）
- `cargo test`、fmt、clippy、i686 全绿
</must_haves>

<tasks>

<task id="09-03-01" type="execute">
  <name>审计端到端捕获测试</name>
  <files>tests/audit.rs</files>
  <read_first>
    - `tests/session_support/mod.rs`（`start_service_with_env`、`connect`、`request`、`send_and_receive`）
    - `src/domain/crypto.rs` 中调用 `authorized(...)` 的处理器（选一个无需硬件即可触发的）
    - `src/audit.rs` 的 JSON 形状
  </read_first>
  <action>
    1. 新建 `tests/audit.rs`，用本地 `Command` 启动 `CARGO_BIN_EXE_skf-service`：
       - `current_dir = CARGO_MANIFEST_DIR`
       - `SKF_WS_ADDR=127.0.0.1:0`、`SKF_HTTP_ADDR=127.0.0.1:0`、`RUST_LOG=info`
       - `stderr` 管道
       解析 stdout 得到端口（复用 `session_support` 的解析逻辑或复制最简版本）。
    2. 用 WS 客户端发送一个会走到 `authorized(...)` 的请求（无 grant，必然 `NotAuthorized`）。优先选择 `SignData`（`src/domain/crypto.rs`）；若其前置参数校验会先失败，则改用任何一种在无授权时即调用 `authorized` 的方法。发送前先在后台线程持续读取 stderr。
    3. 断言：
       - 捕获内容出现 `"audit":true` 且出现 `"authorization.denied"`；
       - 出现 `"reason":"not_authorized"`；
       - 捕获内容不含 `PRIVATE KEY`、`Bearer `、`"pin"`；
       - 进程清理（kill + wait）。
    4. 为避免 flakiness：等待审计行出现最多 15s；发送请求后继续读取。
  </action>
  <acceptance_criteria>
    - `test -f tests/audit.rs` 为真
    - `grep -c 'fn denied_authorization_is_audited' tests/audit.rs` 输出 `1`
    - `grep -c 'authorization.denied' tests/audit.rs` 输出 `>= 1`
    - `cargo test --test audit` 退出码 0
  </acceptance_criteria>
  <verify>`cargo test --test audit`</verify>
</task>
