# Plan 09-02: Combined Exposure Rule for Non-Loopback Binding

<objective>
把阶段 8 的两条独立检查合并为单一的暴露规则：非回环绑定必须同时具备远程 opt-in、TLS 与客户端认证；拒绝发生在 bind 之前、消息列明三项要求、退出码保持 `EXIT_BIND`（BIND-01/02/03）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-09-03 | 仅 opt-in 或仅客户端认证即可远程暴露（无 TLS 明文） | HIGH | 三项必须同时满足才放行 |
| T-09-04 | 改动破坏回环默认行为或 37 夹具 | HIGH | 回环路径完全不变；测试覆盖 |
| T-09-06 | 拒绝发生在 bind 之后，端口短暂暴露 | MEDIUM | 检查位于 `TcpListener::bind` 之前 |
</threat_model>

<must_haves>
- `bind_with_progress` 用单条规则替换两条检查
- 拒绝消息同时提到 opt-in、TLS、client authentication
- 退出码为 `EXIT_BIND`（3），阶段为 `StartupStage::Bind`
- 回环绑定（无 opt-in/TLS/认证）行为不变
- `tests/loopback_gate.rs` 正值带 TLS；新增"有客户端认证但无 TLS 被拒"负值
- `cargo test --test loopback_gate` 通过
</must_haves>

  <name>合并暴露规则</name>
  <files>src/server/mod.rs</files>
  <read_first>
    - `src/server/mod.rs` 的 `bind_with_progress`（`allow_remote` 与 AUTH-03 两处检查）
    - `.planning/phases/09-bind-policy-and-authorization-audit/09-RESEARCH.md`
  </read_first>
  <action>
    1. 把现有两条 `if !ws_socket.ip().is_loopback() …` 检查替换为一条：
       ```rust
       if !ws_socket.ip().is_loopback() {
           let tls_enabled = tls.is_some();
           let auth_enabled = !client_auth.requires_loopback();
           if !(config.allows_remote() && tls_enabled && auth_enabled) {
               return Err(StartupError::Bind(format!(
                   "refusing to bind WebSocket listener to non-loopback address {}; remote binding requires all of: allow_remote: true (or SKF_ALLOW_REMOTE=1), TLS (tls.cert_file and tls.key_file), and client authentication (tls.client_auth: mtls or token)",
                   ws_socket
               )));
           }
       }
       ```
       注意该检查必须在 `TcpListener::bind` **之前**（现状如此）。
    2. 单测（`src/server/mod.rs` 测试模块，需要 rcgen 生成证书、需要 `test_env` 锁清理 TLS 环境）：
       - `remote_bind_without_tls_is_a_bind_error`：opt-in + token、无证书 → `StartupError::Bind`，消息含 `TLS`，`exit_code()==EXIT_BIND`。
       - `remote_bind_with_tls_and_auth_is_allowed`：opt-in + 证书 + token → `bind_with_progress` 成功。
       - `remote_bind_without_opt_in_is_a_bind_error`：证书 + token、无 opt-in → 失败。
       - `loopback_bind_needs_no_opt_in_tls_or_auth`：`127.0.0.1:0` 且无任何配置 → 成功。
    3. 保留 phase 8 的逐项检查测试语义：`mtls`/`token` 仍需 `validate_tls` 通过。
  </action>
  <acceptance_criteria>
