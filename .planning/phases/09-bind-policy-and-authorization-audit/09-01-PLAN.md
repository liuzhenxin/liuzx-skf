# Plan 09-01: Structured Authorization Audit

<objective>
把每一个授权决策（授予、拒绝、过期、设备不可用）记录为结构化、非敏感的审计事件，并在唯一的决策点 `SessionState` 上发射，删除调用方的重复日志（AUD-01/02）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-09-01 | 审计记录携带 PIN/密钥/载荷/令牌 | HIGH | 事件字段固定为 provider/device/application/reason/cleared；脱敏扫描 |
| T-09-02 | 决策发生在多处，审计不完整 | HIGH | 只在 `SessionState` 三方法发射 |
| T-09-05 | 日志注入（`\n`/控制字符）伪造审计行 | MEDIUM | 复用 `logging::sanitize` 清理字段 |
</threat_model>

<must_haves>
- `src/audit.rs` 提供 `AuditEvent`（granted/denied/expired/device-unavailable）与 `AuditReason`
- `AuditEvent::to_json()` 输出单行 JSON，含 `"audit":true` 与 stable `"event"` 名
- `audit::emit` 经 `log::info!`；字段经 `logging::sanitize`
- `SessionState::{grant,authorize,invalidate_device}` 各自发射对应事件
- `domain::mod::note_device_unavailable` 与 `main.rs::device_unavailable` 的重复 `log::info!` 被移除
- 事件结构上不可能包含 PIN/密钥/令牌
- `cargo test --lib`、fmt、clippy 通过
</must_haves>

  <action>
    1. 新建 `src/audit.rs`：
       ```rust
       #[derive(Debug, Clone, Copy, PartialEq, Eq)]
       pub enum AuditReason { NotAuthorized, Expired, DeviceUnavailable }
       impl AuditReason { pub fn as_str(self) -> &'static str; }

       #[derive(Debug, Clone, PartialEq, Eq)]
       pub enum AuditEvent {
           AuthorizationGranted { provider: String, device: String, application: String },
           AuthorizationDenied { provider: String, device: String, application: String, reason: AuditReason },
           AuthorizationExpired { provider: String, device: String, application: String },
           DeviceUnavailable { provider: String, device: String, cleared: usize },
       }

       impl AuditEvent {
           pub fn granted(provider: &str, device: &str, application: &str) -> Self;
           pub fn denied(provider: &str, device: &str, application: &str, reason: AuditReason) -> Self;
           pub fn expired(provider: &str, device: &str, application: &str) -> Self;
           pub fn device_unavailable(provider: &str, device: &str, cleared: usize) -> Self;
           pub fn name(&self) -> &'static str; // "authorization.granted" | "authorization.denied" | "authorization.expired" | "device.unavailable"
           pub fn to_json(&self) -> String;    // {"audit":true,"event":...,"provider":...,"device":...,["application":...,]["reason":...,]["cleared":...]}
       }

       /// Emit one audit record. Fields are sanitized; no secret is ever passed.
       pub fn emit(event: &AuditEvent) { log::info!("{}", event.to_json()); }

       /// Map an `AuthRejection` to an audit reason.
       pub fn reason_for(rejection: crate::session::auth::AuthRejection) -> AuditReason;
       ```
       `to_json` 用 `serde_json::json!` 构造，所有字符串字段先经 `crate::logging::sanitize`。
    2. `src/lib.rs` 增加 `pub mod audit;`（字母序）。
    3. 单测：
       - `granted_event_has_the_expected_json`
       - `denied_event_carries_the_reason`
       - `expired_and_device_unavailable_names`
       - `audit_json_has_no_secret_fields`（断言输出不含 `pin`/`key`/`payload`/`token` 子串）
       - `reason_for_maps_each_rejection`
  </action>

<task id="09-01-02" type="execute">
  <name>在唯一决策点发射审计并去除重复日志</name>
  <files>src/session/mod.rs, src/domain/mod.rs, src/main.rs, tests/log_redaction.rs</files>
  <read_first>
    - `src/session/mod.rs` 的 `grant`/`authorize`/`invalidate_device`
    - `src/domain/mod.rs` 的 `note_device_unavailable`
    - `src/main.rs` 的 `device_unavailable`
  </read_first>
  <action>
    1. `src/session/mod.rs`：
       - `grant(key)`：先构造 `AuditEvent::granted(&key.provider, &key.device, &key.application)`，再 `self.auth.grant(key)`，最后 `crate::audit::emit(&event)`。
       - `authorize(&key)`：调用 `self.auth.check(key)`；`Err(Expired)` 发射 `AuditEvent::expired(...)`；`Err(NotAuthorized)` 发射 `AuditEvent::denied(..., AuditReason::NotAuthorized)`；`Ok` 不发射（避免刷屏）。
       - `invalidate_device(provider, device)`：`let removed = self.auth.invalidate_device(...)`；`if removed > 0 { audit::emit(&AuditEvent::device_unavailable(provider, device, removed)) }`；返回 `removed`。
    2. `src/domain/mod.rs::note_device_unavailable`：删除内部 `log::info!`，直接调用 `state.invalidate_device(...)`（审计由其内部发射）。
    3. `src/main.rs::device_unavailable`：同样删除重复 `log::info!`。
    4. `tests/log_redaction.rs`：确认扫描覆盖 `audit` 相关调用；如审计模块日志行含敏感词则修正（预期不含）。新增不可为空：`grep` 至少命中 `token`/`pin` 等既有词表。
    5. 单测（`src/session/mod.rs` 测试模块）：
       - `grant_then_authorize_succeeds`（既有行为不变）
       - `expired_authorization_is_rejected`（既有行为不变）
       - `invalidate_device_returns_the_cleared_count`（既有行为不变）
       —— 这些既有测试必须继续通过，证明审计发射没有改变决策语义。
  </action>
  <acceptance_criteria>
    - `grep -c 'audit::emit' src/session/mod.rs` 输出 `>= 3`
    - `grep -c 'log::info!' src/domain/mod.rs` 输出 `0`（该文件不再有 info 日志；如仍有其它必要日志需在 SUMMARY 说明）
