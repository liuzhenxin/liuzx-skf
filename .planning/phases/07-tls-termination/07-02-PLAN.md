# Plan 07-02: Secret Safety and Diagnostics for TLS

<objective>
确保 TLS 私钥/证书材料绝不进入日志、`diagnose`、状态文件或发布元数据（TLS-04），并让 `diagnose` 以非敏感布尔反映 TLS 状态；同时复核默认明文路径与 37 夹具不受影响（COMPAT-01）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-07-04 | 私钥内容或路径从 `diagnose`/日志/状态文件泄露 | HIGH | 只输出布尔；测试断言 JSON 与捕获输出不含路径/内容 |
| T-07-06 | TLS 代码在日志宏中记录 `key_file`/`cert_file` 或私钥 | HIGH | 扩展脱敏扫描；源码中 TLS 路径不进入日志宏 |
| T-07-07 | 默认明文行为被 TLS 改动破坏 | HIGH | 37 夹具 + vendor-free 套件 + 明文启动测试 |
</threat_model>

<must_haves>
- `DiagnosticReport` 含 `tls_enabled: bool`、`tls_cert_loaded: bool`；文本与 JSON 渲染都含它们
- `diagnose` 的 JSON 不含证书/私钥路径或内容
- 启动日志只含 `tls=enabled|disabled`（或等价布尔），不含路径
- `tests/log_redaction.rs` 仍绿，且覆盖 TLS 相关日志调用
- `cargo test --test contract_fixtures` 37/37；`cargo check --target i686-pc-windows-gnu` 通过
</must_haves>
