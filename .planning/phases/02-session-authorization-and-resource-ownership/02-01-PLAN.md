# Plan 02-01: Session Skeleton and Registry

<objective>
建立会话的**所有权模型**：会话 ID 生成、会话状态容器、以及一个不拥有会话的注册表。

这一步是后续所有工作的基座——研究（`02-RESEARCH.md` G-1）确认会话状态**不需要任何内部可变性**，因为 `Session::handle` 拿到的是 `&mut self`。因此本计划刻意不引入 `Mutex`/`RwLock` 到会话路径上，只给跨连接共享的注册表加锁。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-02-01 | 会话 ID 可预测，被用作可猜测的凭据 | HIGH | ID 由 `OsRng` 填充 16 字节（128 位）后转 32 位小写十六进制；测试断言两次生成不同且长度为 32 |
| T-02-08 | 注册表持有 `Arc<SessionState>`，使会话在断连后仍存活 → 变成本阶段要消灭的那类泄漏 | HIGH | 注册表只存 `Weak<SessionMarker>`（一个只含 ID 的轻量类型）；**`SessionState` 由 `SessionGuard` 按值持有**。测试断言 guard drop 后注册表条目消失 |
| T-02-12 | 把 `SessionState` 放进 `Arc` 以让注册表引用它 —— 但其中 `Box<dyn DeviceGuard>` 是 `Send` 而非 `Sync`，会使 `Arc<SessionState>` 不是 `Send`，会话无法移入异步任务；若为此新增 `unsafe impl Sync` 则违反 D-22 | HIGH | 注册表引用的是 `Arc<SessionMarker>`（`Send + Sync`，仅含 `SessionId`），会话状态按值持有。此设计使 `SessionGuard: Send` 成立且**不需要任何新的 `unsafe impl`**；由 `tests/session_invariants.rs` 断言 `unsafe` 数量不变 |
| T-02-09 | 注册表被当作通用会话查询入口，重新引入跨会话访问 | HIGH | 接口只有 `register` / `deregister` / `session_count`；**不提供按 ID 查询，也不提供任何修改会话状态的入口**（D-04b）。设备失效由会话自己在其操作失败时检测（见 02-02-03），因此注册表无需触碰会话状态 |

**Security constraint:** 本计划不得接收、存储或记录任何 PIN、密钥或设备标识。
</threat_model>

<must_haves>
- 会话 ID 为 32 位小写十六进制，由 `OsRng` 生成，两次生成不相同
- 注册表**不拥有**会话状态（只持 `Weak`）
- 连接的 `SessionGuard` drop 后，注册表不再包含该会话
- 注册表不提供按 ID 查询会话的能力
- 全 crate 的 `unsafe impl Send`/`Sync` 仍恰好各一处
</must_haves>

    1. 在 `src/lib.rs` 增加 `pub mod session;`，并在模块表中加一行说明：
       `//! | [`session`] | Session identity, authorization table, and opaque handle ownership |`
    2. 创建 `src/session/mod.rs`，包含：
       ```rust
       /// 128-bit session identifier, rendered as 32 lowercase hex characters.
       ///
       /// Never sent to clients (D-03): a distributed identifier becomes a
       /// credential, which would contradict SESS-04's clear-on-disconnect rule.
       #[derive(Debug, Clone, PartialEq, Eq, Hash)]
       pub struct SessionId(String);

       impl SessionId {
           pub fn as_str(&self) -> &str { &self.0 }
           pub fn len_bytes(&self) -> usize { 16 }
       }

       /// Generate a fresh session identifier from the OS CSPRNG.
       pub fn generate_session_id() -> SessionId { /* OsRng + fill_bytes([0u8;16]) → hex */ }
       ```
       `generate_session_id` 必须使用 `rand::rngs::OsRng` 与 `rand::RngCore::fill_bytes`，**不得**使用 `thread_rng`（非密码学保证）。十六进制用现有的 `crate::crypto` 无关的手写格式化即可（`format!("{:02x}", b)`），不新增依赖。
    3. 定义会话状态容器（本计划只含身份与授权占位，句柄表在 02-03 加入）：
       ```rust
       /// Lightweight, `Send + Sync` identity handle for the registry.
       ///
       /// The registry tracks liveness through this marker rather than through
       /// `SessionState` itself: `SessionState` will hold `Box<dyn DeviceGuard>`
       /// values (from plan 02-03), which are `Send` but not `Sync`, so an
       /// `Arc<SessionState>` would not be `Send` and the session could not be
       /// moved into a Tokio task. A marker holding only the id keeps the
       /// registry's `Weak` cheap and avoids any new `unsafe impl`.
       #[derive(Debug)]
       pub struct SessionMarker {
           id: SessionId,
       }

       impl SessionMarker {
           pub fn new(id: SessionId) -> Self { Self { id } }
           pub fn id(&self) -> &SessionId { &self.id }
       }

       /// State owned exclusively by one connection, held **by value**.
       ///
       /// `Session::handle` receives `&mut self`, so nothing here needs interior
       /// mutability: one connection is one session is exclusive access (G-1).
       #[derive(Debug)]
       pub struct SessionState {
           id: SessionId,
       }

       impl SessionState {
           pub fn id(&self) -> &SessionId { &self.id }
       }
       ```
    4. 在 `src/session/mod.rs` 添加 `#[cfg(test)] mod tests`，覆盖：
       - `generate_session_id()` 长度为 32 且全部为小写十六进制字符
       - 连续生成 1000 个 ID，断言无重复（`HashSet` 长度 == 1000）
       - `SessionId::len_bytes() == 16`
       - `SessionState` 暴露的 id 与传入一致
  </action>

<task id="02-01-02" type="execute">

  <files>src/session/registry.rs, src/session/mod.rs</files>
  <read_first>

    - `.planning/phases/02-session-authorization-and-resource-ownership/02-RESEARCH.md` §G-2（注册表只暴露窄接口）、§T-02-08 相关论述

  </read_first>
  <action>
    1. 在 `src/session/mod.rs` 增加 `pub mod registry;`
    2. 创建 `src/session/registry.rs`：
       ```rust
       /// Tracks live sessions **without owning them**.
       ///
       /// Entries are `Weak`, so a session's lifetime is controlled by the
       /// connection that created it. A registry holding `Arc` would keep session
       /// state (and every native handle it owns) alive after disconnect — exactly
       /// the leak class this phase exists to remove.
       #[derive(Debug, Default)]
       pub struct SessionRegistry {
           sessions: std::sync::Mutex<
               std::collections::HashMap<SessionId, std::sync::Weak<SessionMarker>>
           >,
       }
       ```
       实现：
       - `pub fn new() -> Self`
       - `pub fn register(self: &Arc<Self>, marker: Arc<SessionMarker>) -> SessionId`
         —— 插入 `Arc::downgrade(&marker)` 并返回 id；调用方（会话）保留 `Arc<SessionMarker>` 与 `SessionState` 本身
       - `pub fn session_count(&self) -> usize` —— 顺带清理 `Weak` 已失效的条目
       - **不提供** `get(id)` / `list()` / `iter()`
       - **不提供**任何形如 `invalidate_for_device` 的跨会话修改入口。设备失效的检测发生在会话自己的请求路径上（会话持有 `&mut`，无需锁），注册表保持只读查询之外无副作用
    3. `pub struct SessionGuard`：
       ```rust
       /// Owns one session for as long as the connection lives.
       ///
       /// `state` is held **by value**: session state contains `Send`-but-`!Sync`
       /// provider guards, so an `Arc` around it would make the whole session
       /// non-`Send`. Dropping the guard deregisters from the registry and, once
       /// plan 02-03 lands, releases every native handle the session holds.
       pub struct SessionGuard {
           registry: Arc<SessionRegistry>,
           marker: Arc<SessionMarker>,
           state: SessionState,
       }
       impl SessionGuard {
           pub fn id(&self) -> &SessionId { self.marker.id() }
           pub fn state(&self) -> &SessionState { &self.state }
           pub fn state_mut(&mut self) -> &mut SessionState { &mut self.state }
       }
       impl Drop for SessionGuard { /* remove self.marker.id() from registry */ }
       ```
       **静态断言（必须成立）：** `SessionGuard: Send`。在测试中以
       `fn assert_send<T: Send>() {}` + `assert_send::<SessionGuard>();` 固化，避免将来有人把状态改成 `Arc` 而静默破坏它。
    4. 在 `src/session/registry.rs` 添加 `#[cfg(test)] mod tests`，覆盖：
       - `register` 后 `session_count() == 1`
       - drop guard 后 `session_count() == 0`（**这是 T-02-08 的回归测试**）
       - 注册表**不**延长会话寿命：在 guard 之外仅保留注册表，`session_count()` 会随 guard 消失而归零
       - 连续创建 3 个会话，`session_count() == 3`；drop 中间一个后为 2
       - `SessionGuard` 实现 `Send`（`assert_send::<SessionGuard>()` 编译通过）——这是会话能移入 Tokio 任务的前提
  </action>
  <acceptance_criteria>
