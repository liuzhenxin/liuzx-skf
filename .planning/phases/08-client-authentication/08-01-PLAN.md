# Plan 08-01: Client Authentication Configuration and Identity Types

<objective>
让 `tls.client_auth` 从"只接受 none"升级为完整的三态配置（none/mtls/token），并引入可复用的身份类型与常量时间令牌比较；为阶段 8 的服务端集成和绑定策略提供唯一事实来源。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-08-01 | mtls 配置缺少 client CA，客户端证书形同虚设 | HIGH | `validate_tls` 在启动时报错 |
| T-08-02 | 令牌比较可被计时侧信道推断 | MEDIUM | 常量时间 XOR 比较 |
| T-08-08 | 令牌被写入 YAML 并进入版本库 | HIGH | 只接受 env / 文件；不在配置结构中内联令牌 |
| T-08-09 | 未知 `client_auth` 值被当作 none 放行 | HIGH | 未知值一律报错 |
</threat_model>

<must_haves>
- `TlsConfig` 新增 `client_ca_file`、`token_file`
- 环境变量 `SKF_TLS_CLIENT_CA`、`SKF_TLS_TOKEN`、`SKF_TLS_TOKEN_FILE`
- `validate_tls` 覆盖 none/mtls/token 的完整矩阵，未知值报错
- `src/client_auth.rs` 提供 `ClientAuthMode`、`ClientIdentity`、`constant_time_eq`
- `ClientAuthMode::requires_loopback()`：`none` 为 true
- 令牌绝不出现在任何错误消息中
- `cargo test --lib` 通过；fmt/clippy 干净
</must_haves>

    1. `TlsConfig` 增加：

    2. 环境常量与读取：
       - `pub const TLS_CLIENT_CA_ENV: &'static str = "SKF_TLS_CLIENT_CA";`
       - `pub const TLS_TOKEN_ENV: &'static str = "SKF_TLS_TOKEN";`
       - `pub const TLS_TOKEN_FILE_ENV: &'static str = "SKF_TLS_TOKEN_FILE";`
       - `pub fn tls_client_ca_path(&self) -> Option<String>`（env 优先，其次 `client_ca_file`）
       - `pub fn tls_token(&self) -> Option<String>`：`SKF_TLS_TOKEN` 非空直接返回；否则读 `SKF_TLS_TOKEN_FILE` 或 `token_file` 指向的文件，`trim()` 后返回；读失败返回 `None`（由验证层报错）。
    3. 重写 `validate_tls`：
       - (cert,key) 必须同有或同无（保持阶段 7 规则）
       - 解析模式（`tls_client_auth()` 的字符串）：
         - `"none"` → 通过
         - `"mtls"` → 需要 cert+key 且 `tls_client_ca_path().is_some()`，否则 `Err("tls: client_auth 'mtls' requires cert_file, key_file and client_ca_file")`
         - `"token"` → 需要 `tls_token().is_some()`，否则 `Err("tls: client_auth 'token' requires SKF_TLS_TOKEN or token_file")`
         - 其它 → `Err(format!("tls: unknown client_auth '{}' (expected none, mtls or token)", mode))`
    4. 单测（复用 `env_lock()`/`clear_tls_env()`，并扩展 clear 到新常量）：
       - `mtls_without_client_ca_is_rejected`
       - `mtls_with_ca_and_server_cert_is_accepted`
       - `token_without_source_is_rejected`
       - `token_from_token_file_is_accepted`（临时文件写入令牌）
       - `unknown_client_auth_is_rejected`
       - `token_value_is_not_in_the_error_message`
  </action>

<task id="08-01-02" type="execute">
  <name>client_auth 模块：模式、身份与常量时间比较</name>

  <read_first>
    - `.planning/phases/08-client-authentication/08-RESEARCH.md` D-03..D-06
    - `src/config/mod.rs` 的 `tls_client_auth()`
  </read_first>
  <action>
    1. 新建 `src/client_auth.rs`：
       ```rust
       #[derive(Debug, Clone, Copy, PartialEq, Eq)]
       pub enum ClientAuthMode { None, Mtls, Token }

       impl ClientAuthMode {
           pub fn parse(value: &str) -> Result<Self, String>;
           /// `none` must not be exposed on a non-loopback address (AUTH-03).
           pub fn requires_loopback(self) -> bool { matches!(self, Self::None) }
       }

       #[derive(Debug, Clone, PartialEq, Eq)]
       pub enum ClientIdentity {
           Anonymous,
           Token,
           Certificate { subject_cn: Option<String> },
       }

       impl ClientIdentity {
           /// A non-sensitive label safe for logs/audit.
           pub fn class(&self) -> &'static str { "anonymous" | "token" | "certificate" }
           /// Constant-time comparison of a presented bearer token (D-05).
           pub fn token_matches(expected: &[u8], presented: &str) -> bool;
       }

       pub fn constant_time_eq(a: &[u8], b: &[u8]) -> bool;
       ```
       - `token_matches` 接受 `Authorization` 头的原始值，剥离大小写不敏感的 `Bearer ` 前缀后再比较；无前缀或非 UTF-8 视为不匹配。
       - `constant_time_eq`：长度不等返回 false；否则对所有字节做 `diff |= a^b`，返回 `diff == 0`。
    2. `src/lib.rs` 增加 `pub mod client_auth;`（保持模块字母序）。
    3. 单测：
       - `parse_accepts_the_three_known_modes_and_normalizes_case`
       - `parse_rejects_unknown_modes`
       - `only_none_requires_loopback`
       - `constant_time_eq_matches_exact_bytes_only`
       - `token_matches_requires_the_bearer_prefix_and_the_exact_value`
       - `identity_class_is_non_sensitive`
  </action>
