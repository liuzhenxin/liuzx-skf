# Plan 01-03: SKF Provider Abstraction with Failure-Injecting Fake

<objective>
建立 SKF 调用的领域操作抽象：`SkfProvider` trait、拥有单一库实例的原生实现、以及可注入失败并记录调用序列的 fake 实现。

本计划只**建立**抽象与其测试，不把 37 个方法分支迁移到该抽象（D-06：迁移属阶段 2）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-01-03 | trait 暴露 `*mut c_void`/`HANDLE`，使原生指针越过 provider 边界，阶段 2 的不透明标识无法落地 | HIGH | trait 与守卫接口**不得**出现 `HANDLE`、`DEVHANDLE`、`HAPPLICATION`、`HCONTAINER`、`SendHandle`、`*mut c_void`；以 grep 断言（见验收标准） |
| T-01-04 | fake 过度顺从（永远成功），失败路径未被测试，CI 绿而无意义 | HIGH | fake 的 `fail_next` 从第一个提交即存在；五类失败各有断言；负向测试必须在注入失败时返回 `Err` |
| T-01-09 | 原生实现按次加载并释放动态库，使跨请求的原生句柄失效（仓库现存 10 处该模式） | HIGH | `NativeSkfProvider` 持有**恰好一个** `Arc<Library>`；以 `grep -c "Library::new" src/provider/native.rs == 1` 断言 |
| T-01-10 | `unsafe impl Send/Sync` 在 crate 内新增第二处，扩张未定义行为的承担面 | MEDIUM | 断言全 crate 的 `unsafe impl Send`/`unsafe impl Sync` 仍仅存在于 `src/skf/types.rs` 的 `SendHandle` |

**Security constraint:** 不新增任何会记录 PIN 或密钥材质的代码路径；fake 的调用日志只记 `Operation` 枚举值，不记参数内容。
</threat_model>

<must_haves>
- `SkfProvider` trait 覆盖研究确认的 8 个操作组，且不暴露任何原生指针类型
- `NativeSkfProvider` 恰好持有一个 `Arc<Library>`
- `FakeSkfProvider` 支持按调用注入 5 类失败（`PinIncorrect`、`ContainerMissing`、`SymbolUnavailable`、`DeviceRemoved`、`Blocking`）并记录调用序列
- 守卫资源在 `Drop` 中释放，且释放会出现在 fake 的调用序列中
- 不新增 `unsafe impl Send/Sync`
</must_haves>

       `fn enum_devices(&self, present_only: bool) -> ProviderResult<Vec<String>>;`
       `fn device_state(&self, name: &str) -> ProviderResult<u32>;`

       `fn cancel_wait_for_event(&self) -> ProviderResult<()>;`

    - `.planning/phases/01-structural-foundation-and-test-seam/01-RESEARCH.md` §Pitfall 4
  </read_first>
  <action>
    1. 在 `src/provider/mod.rs` 增加 `pub mod native;`。
    2. 创建 `src/provider/native.rs`，实现 `NativeSkfProvider`：
       - 构造函数 `pub fn new(alias: String, lib_path: String) -> ProviderResult<Self>`，内部**恰好调用一次** `unsafe { Library::new(&lib_path) }`，失败时返回 `ProviderError::LibraryLoadFailed { path, arch: std::env::consts::ARCH, detail: e.to_string() }`；成功后构造 `SkfApi::new(lib)` 并存入 `Arc<SkfApi>` 字段。
       - 提供 `pub fn from_config(config: &SkfConfig, alias: &str) -> ProviderResult<Self>`，用 `crate::config::resolve_lib_path(...)` 解析路径，失败返回 `ProviderError::ProviderNotConfigured`。
       - 内部辅助：
         `fn cstring(s: &str) -> ProviderResult<CString>`（含 NUL 时返回 `ProviderError::Native { code: SAR_ILLEGAL_ARGUMENT, context: "CString::new" }`，**不得 unwrap**）
         `fn parse_cstr_list(buf: &[CHAR], size: usize) -> Vec<String>`（逐字搬运 `main.rs` 中 `split(|&c| c == 0).filter(!empty).map(from_utf8_lossy)` 的逻辑）
    3. 守卫实现，全部持有 `Arc<SkfApi>` 与原生句柄，并在 `Drop` 中释放：
       - `NativeDevice { api: Arc<SkfApi>, raw: DEVHANDLE, exposed: DeviceHandle }`，`Drop` 调 `api.dis_connect_dev(self.raw)`（`raw` 为 null 时跳过）
       - `NativeApplication { api, h_dev: DEVHANDLE, raw: HAPPLICATION, exposed }`，`Drop` 调 `close_application`
       - `NativeContainer { api, raw: HCONTAINER, exposed }`，`Drop` 调 `close_container`
       - `NativeDigest { api, h_dev: DEVHANDLE, raw: HANDLE, exposed }`，`Drop` 调 `close_hash` 与 `dis_connect_dev`
       句柄 `exposed` 值来自各 provider 实例内的 `AtomicU64` 计数器（起点 1），**不得**使用原生指针数值。
    4. 每个原生调用后统一比较 `SAR_OK`；失败时返回 `ProviderError::Native { code: ret, context: "<方法名>" }`；`SAR_COULDNOTGETFUNCADDR` 映射为 `ProviderError::SymbolUnavailable { name: "<符号名>" }`。
    5. `verify_pin` 返回 `PinOutcome { success: ret == SAR_OK, retry_count }`，**不得**返回 `Err` 表示 PIN 错误（PIN 错误是正常业务结果）。
    6. **不得**出现第二处 `Library::new`，也不得在守卫方法内重新加载库。
  </action>

       在 `Cargo.toml` 增加

       并写为 `#[cfg(any(test, feature = "test-provider"))] pub mod fake;`。
       **不得**改变 `default` features（D-21 与打包不变性）。
    2. 创建 `src/provider/fake.rs`：
       ```rust
       pub struct FakeSkfProvider {
           alias: String,
           failures: Mutex<HashMap<Operation, VecDeque<SkfError>>>,
           calls: Mutex<Vec<Operation>>,
           next_handle: AtomicU64,
           devices: Mutex<Vec<String>>,      // 供 enum_devices 返回
       }
       ```
    3. 公开 API：
       - `pub fn new(alias: &str) -> Self`
       - `pub fn with_devices(alias: &str, devices: Vec<String>) -> Self`
       - `pub fn fail_next(&self, op: Operation, err: SkfError)` — 追加到该操作队列（FIFO）
       - `pub fn calls(&self) -> Vec<Operation>` — 克隆调用序列
       - `pub fn call_count(&self, op: Operation) -> usize`
       - `pub fn clear_failures(&self)`
    4. 内部 `fn take_failure(&self, op: Operation) -> Option<SkfError>`：先记录 `Operation`，再从队首取注入项；存在时按类型返回对应错误：
       - `SkfError::Blocking(d)` → `std::thread::sleep(d)` 后**正常返回**（用于模拟慢调用；调用方据此验证不会阻塞其他任务，属阶段 3 使用）
       - 其余 → `Err(ProviderError::Injected(err))`
    5. 守卫的 `Drop` 必须记录 `Close*` 操作，使阶段 2 能断言释放：`CloseDevice`、`CloseApplication`、`CloseContainer`、`CloseDigest`。
    6. 句柄值来自 `next_handle`（起点 1000），确定性且与原生指针无关。
    7. 在 `src/provider/fake.rs` 添加 `#[cfg(test)] mod tests`，覆盖：
       - `enum_devices` 返回构造时提供的设备列表
       - `fail_next(Operation::OpenDevice, SkfError::DeviceRemoved)` 后第一次 `open_device` 返回 `Err(ProviderError::Injected(SkfError::DeviceRemoved))`，第二次成功
       - `fail_next(Operation::VerifyPin, SkfError::PinIncorrect)` 后 `verify_pin` 返回 `PinOutcome { success: false, .. }`（**不是** `Err`）
       - `fail_next(Operation::OpenContainer, SkfError::ContainerMissing)` 后返回 `Err`
       - `fail_next(Operation::DigestBegin, SkfError::SymbolUnavailable)` 后返回 `Err(Injected(SymbolUnavailable))`
       - `fail_next(Operation::EnumDevices, SkfError::Blocking(Duration::from_millis(50)))` 后调用耗时 `>= 50ms` 且**成功**返回
       - drop 一个 `DeviceGuard` 后 `call_count(Operation::CloseDevice) == 1`
       - 句柄值确定性：两次 `open_device` 返回不同的可预测递增 `DeviceHandle`
  </action>
