# Plan 01-04: Provider Injection, Ephemeral-Port Server, and Contract Replay

<objective>
把 provider 抽象接入服务器启动路径，使服务器可在临时端口上被测试；把 `win_service` 迁入库 crate；建立端到端契约重放测试，让 37 个方法的 v0.2.0 契约在每次改动后自动校验。

本计划完成后，阶段 1 的成功标准 1、2、3、5 可被机器验证。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-01-11 | 为暴露绑定地址而改写绑定逻辑时改变默认绑定行为（前台 `0.0.0.0:8000`、服务 `127.0.0.1:8000`、WS `127.0.0.1:9001`），造成静默的网络暴露面变化 | HIGH | 默认值以显式 `RunMode` 枚举表达并逐字保留；验收标准以 grep 断言三个默认字符串存在；环境变量覆盖行为保持不变 |
| T-01-12 | 契约重放使用 fake 生成期望值，或在不具备厂商库的平台静默跳过，使 oracle 形同虚设 | HIGH | 期望值只来自 01-01 录制的夹具；跳过路径必须打印原因与跳过方法数（`eprintln!` 且断言输出可 grep）；跳过不得计为通过 |
| T-01-13 | 路由少量分支至 provider 时改变错误码或消息文本 | MEDIUM | 仅路由 5 个不涉及容器/PIN/hash 状态的分支；每个分支的路由改动必须由对应夹具保持通过；错误码与消息字符串逐字保留 |
| T-01-14 | `win_service` 迁入库后 Windows 构建断裂，或服务模式丢失停止信号语义 | MEDIUM | `#[cfg(windows)]` 保持在模块边界；`cargo check --target i686-pc-windows-gnu` 为硬性验收；`run_service` 的 `stop_tx`/`stop_rx` 语义与状态上报顺序不变 |

**Security constraint:** 路由改动不得削弱任何现有错误返回；不得让 provider 的注入错误绕过 `SAR_OK` 检查语义。
</threat_model>

<must_haves>
- 服务器可在 `127.0.0.1:0` 上启动，测试可读到**解析后**的实际端口
- 三个默认绑定值与两个 `SKF_*` 覆盖行为与重构前完全一致
- 37 个夹具在具备厂商库的环境下全部重放通过
- 不具备厂商库时，重放测试**明确报告跳过及原因**，不静默通过
- `cargo check --target i686-pc-windows-gnu` 通过
- `win_service` 位于库 crate 且 Windows 构建路径正确
</must_haves>

    1. 创建 `src/server/mod.rs`，在 `src/lib.rs` 增加 `pub mod server;`。
    2. 定义：
       ```rust
       #[derive(Clone, Copy, PartialEq, Eq, Debug)]
       pub enum RunMode { Console, Service }

       #[derive(Clone, Debug)]
       pub struct ServerOptions {
           pub config_path: String,
           pub ws_addr: String,
           pub http_addr: String,
           pub mode: RunMode,
       }

       impl ServerOptions {
           /// 与重构前完全一致的解析规则：
           /// - SKF_CONFIG 覆盖 config/skf.yaml
           /// - SKF_WS_ADDR 覆盖 127.0.0.1:9001
           /// - SKF_HTTP_ADDR 覆盖 Console=0.0.0.0:8000 / Service=127.0.0.1:8000
           pub fn from_env(mode: RunMode) -> Self { /* ... */ }
       }

       pub struct BoundServer {
           pub ws_addr: std::net::SocketAddr,
           pub http_addr: std::net::SocketAddr,
       }

       /// 先绑定并返回解析后的地址，再由调用方决定何时 serve。
       pub async fn bind(opts: &ServerOptions) -> anyhow::Result<(BoundServer, tokio::net::TcpListener)>
       ```
    3. `bind` 必须用 `listener.local_addr()?` 填充 `BoundServer.ws_addr`（**不是** `opts.ws_addr`），HTTP 同理（先 `TcpListener::bind` 再交给 `warp::serve`，或保留现有 `warp::serve(route).run(addr)` 但把解析后的 HTTP 地址通过先绑定后 `run_incoming` 的方式取得）。
    4. 定义 `pub trait ProviderFactory: Send + Sync + 'static { fn build(&self, config: &SkfConfig) -> std::sync::Arc<dyn SkfProvider>; }`，并提供 `pub struct NativeProviderFactory;` 作为默认实现。
    5. 定义 `pub trait ProviderFactory: Send + Sync + 'static { fn build(&self, config: &SkfConfig) -> std::sync::Arc<dyn SkfProvider>; }`，并提供 `pub struct NativeProviderFactory;` 作为默认实现。
    6. 采用**两段式 API**，使测试无需启动无限循环：
       - `pub async fn bind(opts: &ServerOptions) -> anyhow::Result<(BoundServer, tokio::net::TcpListener, Option<tokio::net::TcpListener>)>` —— **只绑定，不 serve**；两个 listener 分别对应 WS 与 HTTP。测试拿到 `BoundServer.ws_addr` 后自行 `serve`。
       - `pub async fn serve(ws: tokio::net::TcpListener, http: Option<tokio::net::TcpListener>, provider: Arc<dyn SkfProvider>, shutdown: Option<tokio::sync::watch::Receiver<bool>>) -> anyhow::Result<()>` —— 包含 WS 接受循环、HTTP 静态服务与 `tokio::select!` 停止语义，行为逐字保留。
       - `pub async fn run_server<F: ProviderFactory>(opts: ServerOptions, factory: F, shutdown: Option<tokio::sync::watch::Receiver<bool>>) -> anyhow::Result<BoundServer>` —— 组合 `bind` + `serve`，**先通过 `tokio::sync::oneshot` 把 `BoundServer` 发回调用方**，再进入 `serve` 循环，从而在长生命周期下仍能返回解析后的地址。
    7. `src/main.rs` 的 `main()` 改为：按 `--service` 是否存在选择 `RunMode`，调用 `skf_service::server::run_server(ServerOptions::from_env(mode), NativeProviderFactory, None)`。
    8. **显式保留**以下默认字符串（不得改写、不得改变大小写或端口）：
       `"127.0.0.1:9001"`、`"0.0.0.0:8000"`、`"127.0.0.1:8000"`、`"config/skf.yaml"`、环境变量名 `"SKF_CONFIG"`、`"SKF_WS_ADDR"`、`"SKF_HTTP_ADDR"`。
    8. 保留重构前的 CWD 回退行为：当 `config/skf.yaml` 不存在时切换到可执行文件所在目录。
  </action>
