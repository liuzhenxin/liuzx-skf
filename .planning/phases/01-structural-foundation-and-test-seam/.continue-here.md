# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Verify determinism across process restarts, never within one process — a same-process comparison reported "zero undeclared volatility" while `EnumProvider` was in fact order-unstable — structural mitigation: stop the service, start it again, record, then compare with oracle normalization
- [ ] CONSTRAINT: Confirm the service under test is the current build before recording — a launchd `KeepAlive` agent respawned a stale binary and held the ports, so "the service is running" did not mean "the current code is running" — structural mitigation: check the startup log line and confirm no launchd job owns the port before recording

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Same-process determinism check | Recording twice inside one server process compared stable `HashMap` ordering and wrongly reported zero volatility | blocking | Cross-process comparison: kill the service, restart it, record, compare (see `tests/fixtures/v0.2.0/README.md` §How to verify determinism correctly) |
| Recording against a stale process | `com.liuzx.skf-service.plist` with `KeepAlive` respawned an old binary on ports 9001/8000, so a recording would have had ambiguous provenance | blocking | Unload the agent first; start the service explicitly from `target/debug/`; verify via the startup log line |
| Fabricating a native handle | Passing integer `1` as a `DEVHANDLE` to `GenerateRandom` crashed the whole process inside the vendor DLL | advisory | Never fabricate handles in the recorder or tests; the fake provider uses synthetic counters and the proper fix is RES-01 in Phase 2 |
| Cancelling `WaitForDevEvent` too early | If the cancel arrives before the waiter enters the blocking vendor call, the cancel is lost and the wait never returns | advisory | Wait ~800 ms before cancelling and retry when no response is produced; treat the method as a shape check during replay |
| Idealising behaviour while moving code | Two `config` test expectations were written to what the code "should" do (`a%%b` → `a%%b`) instead of what it does (`a%b`) | advisory | Assert observed behaviour for moved code; an idealised assertion is an undetected behaviour change |
