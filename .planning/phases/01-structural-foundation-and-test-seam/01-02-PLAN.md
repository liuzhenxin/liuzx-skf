# Plan 01-02: Library Crate Split and Pure-Logic Extraction

<objective>
把 crate 拆为 library + thin binary，使 `cargo test` 首次拥有可运行的测试目标；把 15 个纯编码函数与配置加载/环境变量展开迁入 `crypto/` 与 `config/`，并为它们建立单测。

本计划是**行为保持**的搬运计划：不改变任何可观测行为，不夹带改进。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-01-06 | 搬运过程中夹带行为变更（改错误消息、改边界处理），使回归不可归因 | HIGH | 函数**逐字搬运**，只在 `use` 与可见性上做最小改动；`cargo test --test fixture_oracle` 与 `cargo test --test contract_fixtures`（01-04 建立后）必须保持通过；更改任何输出字符串将另行任务化 |
| T-01-07 | `[lib]` 拆分改变产物名或链接路径，静默破坏 Windows 打包 | HIGH | 显式验证 `cargo check --target i686-pc-windows-gnu`；确认包名 `skf-service` 使 bin 名保持 `skf-service`；不新增 `[[bin]]` 重命名 |
| T-01-08 | `win_service` 迁入库后调用路径失效 | MEDIUM | 同步更新 `win_service.rs` 中的 `crate::run_server(...)` 调用为新的库路径；`#[cfg(windows)]` 保持在模块边界，使 Linux 构建不受影响 |

**Security constraint carried from CONTEXT.md:** 不得在搬运中把 PIN 或密钥材料引入新的日志/格式化路径（D 系列未变，且 OBS-02 属阶段 6，但本阶段不得使其变差）。
</threat_model>

<must_haves>
- `src/lib.rs` 存在且导出 `crypto`、`config` 模块
- `cargo test` 运行**非零数量**的测试并全部通过（FOUND-01）
- `src/main.rs` 不再包含 15 个纯编码函数的定义
- 两个 YAML 配置继续可解析，键名与语义不变（D-19）
- `SKF_CONFIG`、`SKF_WS_ADDR`、`SKF_HTTP_ADDR`、`RUST_LOG` 继续生效（D-18）
- `cargo check --target i686-pc-windows-gnu` 通过（D-20）
</must_haves>

<task id="01-02-01" type="execute">
  <name>建立 library 目标与模块骨架</name>
  <files>Cargo.toml, src/lib.rs, src/main.rs, src/win_service.rs</files>
  <read_first>
    - `Cargo.toml` — 当前无 `[lib]` 段；包名 `skf-service`；Windows 依赖已按 target 门控
    - `src/main.rs` 第 1–20 行 — 模块声明与 `use` 列表
    - `src/main.rs` 第 238–330 行 — `run_server` 签名与当前位置（本计划暂不移动它）
    - `src/win_service.rs` 第 230–290 行 — `crate::run_server(Some(stop_rx))` 调用点
    - `.planning/phases/01-structural-foundation-and-test-seam/01-RESEARCH.md` §Pattern 1
  </read_first>
  <action>
    1. 创建 `src/lib.rs`：
       ```rust
       pub mod config;
       pub mod crypto;

       #[cfg(windows)]
       pub mod win_service;
       ```
    2. 创建目录与占位模块 `src/crypto/mod.rs`、`src/config/mod.rs`（仅含模块文档注释，函数在后续任务迁入）。
    3. 在 `Cargo.toml` 中**不添加** `[[bin]]` 段（保持默认 bin 名 `skf-service`）。可选：显式添加
       ```toml
       [lib]
       name = "skf_service"
       path = "src/lib.rs"
       ```
       以消除歧义。
    4. 本任务**不触碰** `src/win_service.rs`，也**不触碰** `src/main.rs` 中的 `win_service` 模块声明；`run_server` 本任务仍留在 `main.rs`（将于 01-04-01 迁入 `src/server/mod.rs`）。本任务只做：新增 `src/lib.rs`、新增 `skf` 与 `crypto`/`config` 模块、把 `main.rs` 中对 `crate::skf::...` 的引用改为 `skf_service::skf::...`。
       **具体做法：** 在 `src/lib.rs` 写入 `pub mod config;`、`pub mod crypto;`、`pub mod skf;`；在 `src/main.rs` 删除 `mod skf;` 声明，并把所有 `crate::skf::` 替换为 `skf_service::skf::`；保留 `src/main.rs` 中的 `run_server`、`handle_request` 与 `#[cfg(windows)] mod win_service;` 原地不动。
    5. 保持 `main()` 的 SCM 子命令分派逻辑与 `env_logger::init()` 顺序完全不变。
  </action>
  <acceptance_criteria>
    - `test -f src/lib.rs` 通过
    - `grep -c "pub mod" src/lib.rs` 输出至少 3
    - `grep -c "mod win_service" src/main.rs` 输出 1（本任务不迁移 `win_service`，它在 01-04-02 才迁入库）
    - `cargo check` 退出码为 0
    - `cargo test 2>&1 | grep -E "running [0-9]+ test"` 有输出（即使为 0，本任务只要求目标存在；非零由 01-02-02 达成）
    - `cargo check --target i686-pc-windows-gnu` 退出码为 0
    - `grep -c "\\[\\[bin\\]\\]" Cargo.toml` 输出 0（未重命名 bin）
  </acceptance_criteria>
  <verify>`cargo check && cargo check --target i686-pc-windows-gnu`</verify>
</task>

<task id="01-02-02" type="execute">
  <name>迁移纯编码函数并建立单测</name>
  <files>src/crypto/mod.rs, src/main.rs</files>
  <read_first>
    - `src/main.rs` 第 353–540 行 — 待迁移的 15 个函数完整实现：`hex_to_bytes`、`der_encode_integer`、`der_encode_length`、`der_wrap`、`der_sequence`、`der_set`、`der_oid`、`der_utf8_string`、`der_printable_string`、`der_bit_string`、`der_small_integer`、`der_context_0`、`build_subject_dn`、`build_sm2_spki`、`build_rsa_spki`，以及 `temp_file_path`（**不迁移**，属 I/O）
    - `src/main.rs` 第 465–515 行 — OID 常量（`OID_CN` … `OID_SHA256_WITH_RSA`）随函数一并迁移
    - `src/skf/types.rs` — `ECCPUBLICKEYBLOB`、`RSAPUBLICKEYBLOB` 字段布局
    - `.planning/phases/01-structural-foundation-and-test-seam/01-RESEARCH.md` §Pitfall 5
  </read_first>
  <action>
    1. 把 15 个函数与 OID 常量**逐字**移入 `src/crypto/mod.rs`，仅做以下改动：加 `pub` 可见性；把 `crate::skf::types::...` 引用改为 `crate::skf::types::...`（库内路径不变）。
    2. 在 `src/main.rs` 中删除这些定义，改为 `use skf_service::crypto::*;`（或逐项 `use`）。`temp_file_path` 保持在 `main.rs`。
    3. 在 `src/crypto/mod.rs` 末尾添加 `#[cfg(test)] mod tests`，覆盖：
       - `der_encode_length`：`0`、`127`、`128`、`255`、`256`、`65535` 的精确字节输出（验证 127/128 与 255/256 两个边界从单字节切换为 `0x81`/`0x82`）
       - `hex_to_bytes`：正常偶数长度、奇数长度（末位丢弃）、含非法字符（该项丢弃）、前后空白、空串
       - `der_encode_integer`：全零输入、最高位为 1 时前置 `0x00`、无前导零填充
       - `build_subject_dn`：`"CN=Test,O=Org,C=CN"` 产出可被 `x509-parser` 解析；`C` 使用 PrintableString（tag `0x13`）而其他字段使用 UTF8String（tag `0x0C`）；未知键（如 `X=1`）被跳过；缺少 `=` 的片段被跳过
       - `build_sm2_spki`：对固定 `ECCPUBLICKEYBLOB` 产出以 `0x30` 开头、含 `OID_SM2` 字节序列的 DER
       - `build_rsa_spki`：对固定 `RSAPUBLICKEYBLOB` 产出以 `0x30` 开头、含 `OID_RSA` 与 `NULL`（`0x05 0x00`）的 DER
    4. **禁止**修改任何函数体的逻辑、字符串或常量值。
  </action>
  <acceptance_criteria>
    - `cargo test crypto` 退出码为 0 且测试数 `>= 6`
    - `grep -c "pub fn der_encode_length" src/crypto/mod.rs` 输出 1
    - `grep -c "pub fn build_subject_dn" src/crypto/mod.rs` 输出 1
    - `grep -c "fn der_encode_length" src/main.rs` 输出 0（已完全迁出）
    - `grep -c "OID_SM2" src/crypto/mod.rs` 输出至少 1
    - `grep -c "fn temp_file_path" src/main.rs` 输出 1（I/O 函数保留原地）
    - `cargo check` 退出码为 0
  </acceptance_criteria>
  <verify>`cargo test crypto && cargo check`</verify>
</task>

    - `src/main.rs` 第 112–152 行 — `expand_env_vars` 完整实现（含未闭合 `%` 与未知变量的处理）
    - `src/main.rs` 第 48–63 行 — `get_lib_path` 的 OS 选择与大小写回退逻辑
    - `config/skf.yaml` 与 `packaging/windows/skf-windows-x86.yaml` — 必须继续可解析的两个配置（D-19）
    - `.planning/phases/01-structural-foundation-and-test-seam/01-RESEARCH.md` §Pitfall 7
  </read_first>
  <action>
    1. 把 `SkfConfig` 定义移入 `src/config/mod.rs` 并加 `pub`。
    2. 把 `expand_env_vars` 从 `SkfContext` 的关联函数改为 `src/config/mod.rs` 中的自由函数 `pub fn expand_env_vars(path: &str) -> String`，**逻辑逐字保留**（包括未知变量保留 `%VAR%`、未闭合 `%` 原样输出的行为）。
    3. 新增 `pub fn load(path: &str) -> anyhow::Result<SkfConfig>`，读取文件并 `serde_yaml::from_str`。错误消息**必须**与当前实现一致：`"failed to read config '{}': {}"`。
    4. 新增纯函数 `pub fn resolve_lib_path(libs: &HashMap<String, HashMap<String, String>>, provider: &str, os: &str) -> anyhow::Result<String>`，逐字搬运 `get_lib_path` 的查找与错误消息逻辑（保留 `"Provider '{}' not configured for OS '{}'. Avail Provs: {:?}"` 原文），并调用 `expand_env_vars`。`SkfContext::get_lib_path` 改为委托该函数，**不改变**其可观测行为。
    5. 新增 `pub fn validate(config: &SkfConfig, os: &str) -> Vec<String>`，返回诊断字符串（不 panic、不终止）：默认 provider 不在 `libs` 中；某 provider 缺失当前 OS 路径；路径经展开后仍含未解析的 `%`；`vendor` 中引用了不存在的 provider 别名。**本阶段只产出诊断，不改变启动行为**（fail-fast 属后续阶段）。
    6. 在 `src/config/mod.rs` 添加 `#[cfg(test)] mod tests`，覆盖：
       - `expand_env_vars("%NOPE%")` 返回 `"%NOPE%"`（未知变量保留）
       - `expand_env_vars("%UNCLOSED")` 返回 `"%UNCLOSED"`（未闭合保留）
       - `expand_env_vars("a%%b")` 行为与现实现一致（空变量名时原样输出）
       - `resolve_lib_path` 对 `"GM3000"` 与 `"gm3000"` 均能命中（大小写回退）
       - `resolve_lib_path` 对未知 provider 返回错误且消息含 `Provider 'X' not configured`
       - `load("config/skf.yaml")` 成功且 `default == "GM3000"`
       - `load("packaging/windows/skf-windows-x86.yaml")` 成功且 `GM3000` 的 `windows` 值为 `native\\GM3000\\windows\\mtoken_gm3000.dll`
       - 两处 `validate` 对上述两个配置返回空诊断
    7. `main.rs` 中的 `SkfConfig` 使用点改为 `use skf_service::config::SkfConfig;`。
  </action>
  <acceptance_criteria>
