# Plan 07-01: Optional TLS Termination for the WebSocket Listener

<objective>
让 WebSocket 监听器可以选择性地以 TLS 提供服务（`rustls` + `ring`），并保持默认明文回环不变。证书/私钥在 `bind_with_progress` 中加载：加载失败是致命配置错误（`StartupError::Config`，退出码 1）。TLS 为纯增量，37 个夹具无需改动（TLS-01/02/03、COMPAT-01）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-07-01 | 私钥被写入日志/错误消息/状态文件 | HIGH | 只记录类别与布尔；不记录路径或内容；后续 07-02 加测试 |
| T-07-02 | 证书/私钥加载失败被静默忽略，服务以明文启动 | HIGH | 加载失败 → `StartupError::Config`（exit 1），绝不回退明文 |
| T-07-03 | 握手失败中断 accept 循环（DoS） | MEDIUM | 只记录类别并丢弃连接；许可照常释放 |
| T-07-04 | 连接信号量未覆盖握手，握手洪泛绕过 64 上限 | MEDIUM | 许可在握手前获取并持有到连接结束 |
| T-07-05 | 改动破坏默认明文路径或 37 夹具 | HIGH | TLS 默认关闭；`contract_fixtures` 与 vendor-free 套件必须保持 |
</threat_model>

<must_haves>
- `SkfConfig` 有具名 `tls: Option<TlsConfig>`，含 `cert_file`/`key_file`/`client_auth`；env 覆盖生效
- `client_auth` 非 `none` 时启动报错（阶段 8 才实现）
- `bind_with_progress` 在配置了 TLS 时用 `ring` provider 建 `ServerConfig`；证书/私钥不可读 → `StartupError::Config`
- 连接处理泛型化到 `AsyncRead + AsyncWrite + Unpin + Send`；明文与 TLS 共用同一循环
- 无 `tls:` 配置时行为与 v0.3.0 完全一致（明文）
- `cargo check --target i686-pc-windows-gnu` 通过
- `tests/tls.rs` 覆盖明文默认与 TLS 成功路径（rcgen 生成证书）
</must_haves>

<task id="07-01-02" type="execute">

  <action>
    1. `PreparedServer` 增加 `pub tls: Option<tokio_rustls::TlsAcceptor>`。
    2. 新增私有函数 `build_tls_acceptor(config: &SkfConfig) -> Result<Option<TlsAcceptor>, StartupError>`：
       - `config.validate_tls().map_err(StartupError::Config)?`
       - 无 cert/key → `Ok(None)`
       - 否则解析路径（相对 exe 目录：`server::prepare_working_directory` 已保证 cwd；用 `Path::new(path)`，若相对则相对 exe 目录拼接）；用 `rustls_pemfile::certs`/`private_key` 读取；证书空或私钥缺失 → `StartupError::Config("TLS certificate could not be loaded".into())` 之类的**类别消息**（不含路径）。
       - 用显式 `ring` provider：
         ```rust
         let provider = std::sync::Arc::new(rustls::crypto::ring::default_provider());
         let cfg = rustls::ServerConfig::builder_with_provider(provider)
             .with_safe_default_protocol_versions()
             .map_err(|e| StartupError::Config(format!("TLS configuration error: {e}")))?
             .with_no_client_auth()
             .with_single_cert(certs, key)
             .map_err(|_| StartupError::Config("TLS certificate could not be loaded".into()))?;
         Ok(Some(tokio_rustls::TlsAcceptor::from(std::sync::Arc::new(cfg))))
         ```
    3. `bind_with_progress` 在 `on_stage(Provider)` 之后、`on_stage(Bind)` 之前调用 `build_tls_acceptor`，并把结果放进 `PreparedServer`；启动日志只输出 `tls=enabled|disabled`（不含路径）。
    4. 单测（用 `rcgen` 或测试内直接构造 PEM；若此刻 `rcgen` 已可用则用）：
       - `no_tls_config_yields_no_acceptor`；
       - `bad_cert_path_is_a_config_error`（配置指向不存在文件 → `StartupError::Config`，且消息不含该路径）。
  </action>
