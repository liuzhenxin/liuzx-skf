# Plan 08-02: Server-Side mTLS and Bearer-Token Enforcement

<objective>
把配置变成强制：`mtls` 模式构建 `WebPkiClientVerifier`（无效/缺失客户端证书在 TLS 握手中被拒），`token` 模式在 WebSocket 升级回调中校验 `Authorization: Bearer`，并把已认证身份传给会话（AUTH-01/02/04）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-08-03 | mtls 配置下误用 `with_no_client_auth`，客户端证书不校验 | HIGH | 按模式选择 verifier；单测覆盖 |
| T-08-04 | 令牌校验发生在升级之后，未认证连接已建立 | HIGH | 用 `accept_hdr_async_with_config` 在升级前拒绝 |
| T-08-05 | 令牌或客户端证书被写入日志/诊断 | HIGH | 只传递并记录 `ClientIdentity::class()` |
| T-08-10 | 非 `Send + 'static` 回调导致编译失败或泄漏 | LOW | 回调捕获 `Arc<ClientAuth>` |
</threat_model>

<must_haves>
- `build_tls_acceptor` 在 `mtls` 时用 `WebPkiClientVerifier` 并加载 client CA
- `PreparedServer` 暴露 `client_auth: ClientAuthMode` 与 `token: Option<Arc<[u8]>>`
- 所有连接路径统一使用 `accept_hdr_async_with_config`
- `token` 模式的升级回调在缺少/错误令牌时返回 401 并拒绝连接
- 身份提取：mTLS → CN（`x509-parser`）；token → `Token`；none → `Anonymous`
- `SessionFactory::create(ClientIdentity)`；`main.rs` 只记录身份类别
- `cargo check --all-targets`、`cargo test --lib` 通过
</must_haves>

  <read_first>
    - `src/server/mod.rs` 的 `build_tls_acceptor`、`load_tls_material`、`PreparedServer`、`bind_with_progress`
    - `src/client_auth.rs`
    - `.planning/phases/08-client-authentication/08-RESEARCH.md`（rustls verifier API）
  </read_first>
  <action>
    1. `PreparedServer` 增加：
       ```rust
       pub client_auth: crate::client_auth::ClientAuthMode,
       /// Expected bearer token bytes; `None` unless the mode is `token`.
       pub token: Option<std::sync::Arc<[u8]>>,
       ```
    2. `build_tls_acceptor` 改为接收 `mode: ClientAuthMode`：
       - `Mtls`：读取 `tls_client_ca_path()` 指向的 PEM，构造 `RootCertStore`（`add` 每个证书；至少一个，否则配置错误），
         ```rust
         let verifier = rustls::server::WebPkiClientVerifier::builder(std::sync::Arc::new(roots))
             .build()
             .map_err(|_| "TLS client CA could not be used".to_string())?;
         ... .with_client_cert_verifier(verifier).with_single_cert(certs, key)
         ```
       - 其它模式：`.with_no_client_auth()`（保持阶段 7）。
       - 注意：`Mtls` 必须有 cert+key（已在 `validate_tls` 保证）。
    3. `bind_with_progress`：解析模式 `ClientAuthMode::parse(&config.tls_client_auth())`，据此构建 acceptor，并加载令牌：
       ```rust
       let token = if mode == ClientAuthMode::Token {
           config.tls_token().map(|t| Arc::<[u8]>::from(t.into_bytes()))
       } else { None };
       ```
       启动日志只记录 `client_auth={none|mtls|token}`，绝不记录令牌。
    4. 单测：
       - `mtls_mode_without_ca_is_a_config_error`
       - `mtls_mode_builds_a_client_verifier`（rcgen 生成 CA + 服务器证书）
       - `token_mode_exposes_no_acceptor_but_carries_the_token`
  </action>

    - `grep -c 'pub token: Option' src/server/mod.rs` 输出 `1`
    - `grep -c 'WebPkiClientVerifier::builder' src/server/mod.rs` 输出 `1`
    - `grep -c 'with_client_cert_verifier' src/server/mod.rs` 输出 `1`

<task id="08-02-02" type="execute">
  <name>升级回调中的令牌校验与身份提取</name>
  <files>src/server/mod.rs</files>
  <read_first>
    - `src/server/mod.rs` 的 `admit`、`run_connection`、`serve`
    - `src/client_auth.rs` 的 `ClientIdentity`、`token_matches`
  </read_first>
  <action>
    1. `admit`/`run_connection` 传递 `client_auth: ClientAuthMode` 与 `token: Option<Arc<[u8]>>`（`PreparedServer` 中克隆）。
    2. TLS 接受后提取身份：
       ```rust
       fn identity_from_tls(mode: ClientAuthMode, stream: &TlsStream<TcpStream>) -> ClientIdentity
       ```
       `Mtls` 时取 `stream.get_ref().1.peer_certificates()` 的叶子证书，用 `x509_parser::parse_x509_certificate` 提取 CN，返回 `Certificate { subject_cn }`；其余返回 `Anonymous`。
    3. `run_connection` 用 `accept_hdr_async_with_config` 替换 `accept_async_with_config`：
       - 回调捕获 `mode` 与 `token`；
       - `Token` 模式：读取 `Authorization` 头，`ClientIdentity::token_matches` 失败则
         ```rust
         return Err(tokio_tungstenite::tungstenite::http::Response::builder()
             .status(tokio_tungstenite::tungstenite::http::StatusCode::UNAUTHORIZED)
             .body(None)
             .expect("static response"));
         ```
       - `Token` 模式成功返回 `ClientIdentity::Token`；其它模式返回给定身份。
       - 提示：`accept_hdr_async_with_config` 的回调是 `FnOnce`，但 `run_connection` 需要先算身份再建会话；把身份计算放在回调外用 `Cell`/`Arc<Mutex<Option<ClientIdentity>>>` 捕获，或用 `let mut identity` 由闭包写入（闭包 `move` + `Send`）。实现时以编译通过为准。
    4. 升级后调用 `sessions.create(identity)`（08-02-03 改签名）。
    5. 单测：
       - `token_mismatch_rejects_the_upgrade`（用 `tokio_tungstenite::client_async` 不带/带错头，断言错误）
       - `valid_token_is_accepted`（允许通过，后续在 08-03 端到端）
       - `cn_is_extracted_from_a_client_certificate`（构造 DER，验证 CN）
  </action>
  <acceptance_criteria>
    - `grep -c 'accept_hdr_async_with_config' src/server/mod.rs` 输出 `1`
    - `grep -c 'fn identity_from_tls\|fn extract_subject_cn' src/server/mod.rs` 输出 `>= 1`
    - `grep -c 'StatusCode::UNAUTHORIZED' src/server/mod.rs` 输出 `1`
    - `grep -c 'token_matches' src/server/mod.rs` 输出 `1`
    - `cargo test server::` 退出码 0
  </acceptance_criteria>
  <verify>`cargo test server::`</verify>
