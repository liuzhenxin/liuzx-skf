# Plan 03-03: Non-Loopback Bind Requires Explicit Opt-In

<objective>
默认拒绝把 WebSocket 服务绑定到非回环地址；只有 YAML 具名键 `allow_remote: true` 或环境变量 `SKF_ALLOW_REMOTE` 为真时才允许。拒绝发生在 `TcpListener::bind` **之前**，进程以非零退出并给出明确指出开关名的错误。

实现 03-CONTEXT D-16（YAML + 环境变量任一）、D-17（启动即拒绝）、D-18（仅 WebSocket）、D-19（解析后 `SocketAddr` 判回环）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-03-10 | 误绑 `0.0.0.0` 把无认证的设备操作接口暴露到网络 | HIGH | `0.0.0.0`/`::` 一律视为非回环并默认拒绝 |
| T-03-11 | 用 `localhost` 字面量绕过检测，或 `127.0.0.2` 漏判 | HIGH | 先解析为 `SocketAddr` 再用 `is_loopback()` |
| T-03-12 | 新增 YAML 键破坏 `#[serde(flatten)]` 解析（D-07） | MEDIUM | 使用**具名**字段 `allow_remote`，serde 会优先绑定具名字段而非 flatten map |
| T-03-13 | opt-in 开关被静默忽略 | MEDIUM | 测试覆盖 YAML、env、两者皆无、两者皆为假四种组合 |
</threat_model>

<must_haves>
- `SkfConfig` 有具名 `allow_remote: Option<bool>` 字段，默认 `None`
- 环境变量 `SKF_ALLOW_REMOTE` 为 `1`/`true` 时视为 opt-in
- `bind` 在 `TcpListener::bind` 之前解析并校验 WS 地址；非回环且未 opt-in → `Err`
- 错误消息同时包含 `allow_remote` 与 `SKF_ALLOW_REMOTE`
- `config/skf.yaml` 与夹具解析不受影响（`cargo test` 全绿）
- `tests/loopback_gate.rs` 覆盖拒绝/允许路径
</must_haves>

  <action>
    1. 在 `SkfConfig` 结构中新增具名字段：
       ```rust
       /// Explicit opt-in for binding the WebSocket listener to a non-loopback
       /// address. `None`/`Some(false)` means loopback-only.
       ///
       /// Named (not flattened) on purpose: an unnamed top-level key would be
       /// captured by `libs`' `#[serde(flatten)]` and could break parsing.
       #[serde(default)]
       pub allow_remote: Option<bool>,
       ```
       确保 `#[serde(flatten)]` 仍用于 `libs`。
    2. 在 `impl SkfConfig` 增加：
       ```rust
       /// Environment variable that opts in at runtime.
       pub const REMOTE_ENV: &'static str = "SKF_ALLOW_REMOTE";

       /// Whether non-loopback binding is permitted.
       ///
       /// YAML `allow_remote: true` or `SKF_ALLOW_REMOTE=1|true` (case-insensitive)
       /// both opt in; either is sufficient. Absent/false everywhere → false.
       pub fn allows_remote(&self) -> bool {
           if self.allow_remote == Some(true) { return true; }
           matches!(std::env::var(Self::REMOTE_ENV).ok().as_deref().map(|v| v.trim().to_ascii_lowercase()), Some(v) if v == "1" || v == "true")
       }
       ```
    3. 增加 `#[cfg(test)]` 单元测试：
       - `yaml_allow_remote_true_opts_in`：反序列化 `allow_remote: true` 的 YAML，断言 `allows_remote()` 为真（注意 env 可能干扰：测试前 `remove_var`）。
       - `absent_allow_remote_is_loopback_only`。
       - `env_var_opts_in`：`set_var("SKF_ALLOW_REMOTE", "1")` 后为真；测试结束 `remove_var`。
       - `flattened_providers_still_parse`：一个含 `allow_remote: true` + provider 条目的 YAML 仍能解析出 `libs`。
  </action>

  <action>
    1. 在 `bind` 中，取得 `config` 后、构造 `listener` 前：
       - 解析 WS 地址：`let ws_socket = resolve_addr(&opts.ws_addr)?;`，其中
         ```rust
         fn resolve_addr(addr: &str) -> anyhow::Result<SocketAddr> {
             use std::net::ToSocketAddrs;
             addr.to_socket_addrs()
                 .map_err(|e| anyhow::anyhow!("invalid WS address '{}': {}", addr, e))?
                 .next()
                 .ok_or_else(|| anyhow::anyhow!("WS address '{}' resolved to nothing", addr))
         }
         ```
       - 校验：`if !ws_socket.ip().is_loopback() && !config.allows_remote() { return Err(anyhow::anyhow!("refusing to bind WebSocket listener to non-loopback address {} without explicit opt-in; set allow_remote: true in the config or SKF_ALLOW_REMOTE=1", ws_socket)); }`
       - 绑定改用解析后的地址：`TcpListener::bind(ws_socket)`，错误消息保留原有 `"failed to bind WebSocket listener on {}"` 文本（用 `ws_socket`）。
    2. **不要**对 `opts.http_addr` 做同样校验（D-18：HTTP demo 保持既有默认）。
    3. 保持 `BoundServer.ws_addr = listener.local_addr()` 不变。
  </action>
