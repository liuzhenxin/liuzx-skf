# Plan 06-02: Local Diagnostics, Protocol Version, and Restricted Methods

<objective>
新增跨平台 `diagnose` 子命令，报告五个启动阶段与运行中状态，且只输出非敏感事实（OBS-03/04）；协议接受可选 `apiVersion` 并新增 `GetProtocolVersion`（REL-01）；受限方法 `{IssueCertificate, Transmit}` 保持存在，默认行为不变，仅在 `SKF_RESTRICT_LEGACY=1` 时返回文档化 `-100`（REL-02）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-06-05 | 诊断输出泄露库路径/配置值 | HIGH | 报告只有阶段布尔、别名、端口、uptime、错误类别；不打印任何路径 |
| T-06-06 | 新增协议字段破坏 v0.2.0 客户端 | HIGH | `apiVersion` 为可选且 `#[serde(default)]`；旧客户端不发送即视为 1；37 夹具回归 |
| T-06-07 | 新方法使契约完备性测试失败或掩盖真实漂移 | MEDIUM | `ADDITIVE_METHODS` 显式白名单 + 在夹具 README 与 RELEASE-NOTES 记录为增补 |
| T-06-08 | 受限方法默认被拒绝，破坏夹具 | HIGH | 默认不拒绝；只有环境变量开启时才返回 `-100` |
| T-06-09 | `apiVersion` 过高被静默忽略导致客户端误判 | MEDIUM | `> 1` 返回文档化 `-1` |
</threat_model>

<must_haves>
- `diagnose [--config <path>] [--json]` 在所有平台可用，报告 `config_loaded`/`provider_alias`/`provider_resolved`/`library_file_present`/`library_loaded`/`listener_bound`/`listener_bindable`/`ws_addr`/`uptime_seconds`/`state`/`stage`/`code`
- 诊断输出不含任何库路径或配置值
- `RpcRequest` 有可选 `api_version`；`>1` 返回 `-1` 文档化消息
- `GetProtocolVersion` 返回 `{"min":1,"current":1,"service":"0.3.0"}`
- `EXPECTED_METHODS` 增补 `GetProtocolVersion`，并有 `ADDITIVE_METHODS` 白名单
- 受限方法默认可用；`SKF_RESTRICT_LEGACY=1` 时返回 `-100`
- `Cargo.toml` 版本为 `0.3.0`
- 37/37 契约、`cargo test`、fmt/clippy/i686 全部通过
</must_haves>

  <action>
    新建 `src/diagnostic.rs`：
    ```rust
    #[derive(Debug, Clone, serde::Serialize)]
    pub struct DiagnosticReport {
        pub config_loaded: bool,
        pub config_error_class: Option<String>,   // "io" | "parse"
        pub provider_alias: String,
        pub provider_resolved: bool,
        pub provider_error_class: Option<String>, // "not_configured"
        pub library_file_present: bool,
        pub library_loaded: bool,
        pub library_error_class: Option<String>,  // "load_failed"
        pub listener_bound: bool,                 // service-state says Running
        pub listener_bindable: bool,              // probe bind of the configured addr
        pub ws_addr: String,
        pub state: Option<String>,
        pub stage: Option<String>,
        pub code: Option<u32>,
        pub address: Option<String>,
        pub uptime_seconds: Option<u64>,
    }

    pub fn run(config_path: &str, ws_addr: &str, state_file: Option<&std::path::Path>) -> DiagnosticReport;
    pub fn render_text(r: &DiagnosticReport) -> String;
    pub fn render_json(r: &DiagnosticReport) -> String;
    ```
    检查实现：
    - `config::load(config_path)`：Ok → `config_loaded=true`；Err → 依 `std::io` 错误 vs 其它归类 `io`/`parse`（用 `err.to_string()` 的前缀或 `err.downcast_ref`；不输出 message）。
    - 成功则 `provider_alias = config.default`；`resolve_lib_path(..., OS)` → `provider_resolved`。
    - 解析成功则 `library_file_present = Path::new(&resolved).exists()`；`library_loaded = NativeSkfProvider::new(&alias, &resolved).is_ok()`。
    - `listener_bindable`：解析 `ws_addr` 为 `SocketAddr`（用 `ToSocketAddrs`），若为 `0.0.0.0`/`::` 或非回环**不影响诊断**（诊断不绑定非回环以避免安全副作用；若地址非回环则 `listener_bindable=false` 并说明）。用 `std::net::TcpListener::bind(addr)` 探测后 drop。
    - `state_file` 存在则 `service_state::read`；`state`/`stage`/`code`/`address` 取文件值；`listener_bound = state=="running"`；`uptime_seconds = now - started_at`（`started_at` 解析为 u64）。
    - **绝不**把 `resolved` 路径写入报告。
    `src/lib.rs` 增加 `pub mod diagnostic;`。
    `src/main.rs`：在 Windows SCM 分派**之前**解析子命令：
    ```rust
    let args: Vec<String> = std::env::args().collect();
    if args.get(1).map(String::as_str) == Some("diagnose") {
        let json = args.iter().any(|a| a == "--json");
        let config_path = std::env::var("SKF_CONFIG").unwrap_or_else(|_| "config/skf.yaml".into());
        let ws_addr = std::env::var("SKF_WS_ADDR").unwrap_or_else(|_| "127.0.0.1:9001".into());
        let state = exe_dir().map(|d| d.join("service-state.json"));
        let report = skf_service::diagnostic::run(&config_path, &ws_addr, state.as_deref());
        println!("{}", if json { render_json(&report) } else { render_text(&report) });
        return Ok(());
    }
    ```
    注意 Windows 的 `main()` 已有 `#[cfg(windows)] { match argv.get(1)... }`；把 `diagnose` 分支放在其**之前**，确保所有平台可用。`exe_dir()` 可用 `std::env::current_exe().parent()`。
    单测（`diagnostic.rs` 内）：
    - `missing_config_reports_not_loaded`：不存在的路径 → `config_loaded=false`，`config_error_class=Some("io")`；
    - `report_never_contains_the_library_path`：构造一个指向不存在文件的临时 YAML，运行 `run`，断言 `render_json` 不含该路径字符串；
    - `render_json_parses_and_has_required_keys`：断言 JSON 含 `config_loaded`/`provider_alias`/`listener_bindable`。
  </action>
