# Plan 01-01: Record and Freeze the v0.2.0 Contract

<objective>
在**改动任何生产代码之前**，用当前未修改的代码录制 37 个方法的真实响应，把响应连同"易变字段清单"一起固化为回归夹具，并提供能证明该夹具会失败的负向自检。

这是阶段 1 的第一个可交付物，也是唯一不可逆的顺序约束（D-09、D-10）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-01-01 | 循环论证：夹具由新写的 fake provider 生成，再断言同一 fake 的输出，测试不证明任何事 | HIGH | 录制工具只通过 WebSocket 连接**真实运行的服务**；本计划不新增任何 provider 或 fake；计划明确禁止在录制阶段引入 fake |
| T-01-02 | 事后放宽 normalize 让失败测试变绿，静默删除断言 | HIGH | `normalize` 与 `response` 在**同一次提交**中写入；提交信息必须声明易变字段评审结论；负向自检证明 oracle 可失败 |
| T-01-05 | 夹具中混入真实 PIN、私钥或会话密钥（录制时使用了真实凭据） | MEDIUM | 录制仅使用无设备环境（无 PIN 可用）；提交前运行密钥材料扫描；`provenance` 记录 `observed_with_device: false` |

**Non-goals:** 本计划不修改 `src/` 下任何文件。若发现必须修改生产代码才能录制，停下并回到讨论阶段。
</threat_model>

<must_haves>
- 37 个方法的夹具文件存在于 `tests/fixtures/v0.2.0/`
- 每个夹具包含 `request`、`response`、`normalize`、`provenance` 四个字段
- 夹具提交时间早于任何 `src/` 修改（可由 git 历史验证）
- 存在证明 oracle 能失败的负向测试
- 不存在由 fake provider 生成的夹具
</must_haves>

    工具必须：
    1. 使用 `require('../api/skf_api')` 中已有的方法包装，**不新写请求构造逻辑**（保证参数顺序与生产一致）。
    2. 覆盖以下 37 个方法，每个产生一个夹具文件：

    5. `DigestUpdate`/`DigestFinal`/`CloseHash` 必须在**同一连接内**先调用 `DigestInit` 并使用其返回的 handle（RESEARCH.md 开放问题 3）。
    6. 写入结构：
       ```json
       { "method": "<name>", "request": {...}, "response": {...}, "normalize": {...}, "provenance": {...} }
       ```
       其中 `normalize` 的值形如 `"<opaque:usize>"`、`"<random:base64>"`、`"<regex:CSR\\d{8}>"`、`"<volatile:retry_count>"`；`provenance` 含 `recorded_from`（`git rev-parse HEAD` 输出）、`recorded_at`、`requires_hardware`（布尔）、`observed_with_device: false`、`placeholder_params`（数组）、`volatile_fields_reviewed: true`。
    7. 全部完成打印 `RECORDED=<n>` 与逐方法的状态行；不得因单个方法失败而中断整轮录制。
  </action>

  <action>
    创建 `tests/fixture_oracle.rs`，本阶段只包含比较器与自检，不连接服务器（服务器驱动在 01-04 加入）。

    必须实现：
    1. `fn apply_normalize(value: serde_json::Value, spec: &serde_json::Value) -> serde_json::Value` — 递归遍历 `spec`；当 `spec` 的某路径值是以 `<` 开头 `>` 结尾的字符串时，用该标记字符串替换实际值；否则递归进入对象/数组。
    2. `fn load_fixture(path: &Path) -> Fixture`，结构体字段 `method: String`、`request: Value`、`response: Value`、`normalize: Value`、`provenance: Value`。
    3. `#[test] fn oracle_rejects_mutated_response()` —— **不依赖磁盘夹具**：在测试内用 `serde_json::json!` 构造一个内存夹具（`response = {"error":0,"result":"OK","id":1}`、`normalize = {"result":"<opaque>"}`），把 `response["error"]` 改为 `-99`，断言 `apply_normalize(mutated, &normalize) != response`。
    4. `#[test] fn oracle_accepts_only_normalized_differences()` —— 使用同一内存夹具：仅替换 `normalize` 声明的路径，断言归一化后**相等**；再替换一个**未声明**的路径（例如 `id`），断言**不等**。
    5. `#[test] fn all_fixtures_are_wellformed()` —— 遍历 `tests/fixtures/v0.2.0/*.json`；若目录不存在或为空，打印 `no fixtures yet` 并**返回**（不失败），使本任务可在录制前独立通过；否则断言每个文件含四个必需字段、`method` 与文件名一致、`provenance.volatile_fields_reviewed == true`，并打印夹具数量。

    **重要：** 夹具文件的完整性与数量下限（`>= 37`）在任务 01-01-03 中验证，不在本任务中——本任务必须先于录制完成，因此不得依赖录制产物。

    同时创建 `tests/fixtures/v0.2.0/README.md`，说明：夹具来自重构前代码；`normalize` 冻结于录制时；**任何事后修改 `normalize` 都必须视为契约变更并在提交信息中说明**；`observed_with_device: false` 表示成功路径尚未在真实设备上录制。
  </action>
