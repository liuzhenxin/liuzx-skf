# Plan 04-03: CI Gate, Contract Replay on x86_64 macOS, and Gate Self-Test

<objective>
新增 PR/主分支 CI，运行格式、lint、硬件无关测试、契约重放与 i686 编译检查；并用一个可执行的 self-test 证明门禁对失败测试敏感（QUAL-03/04，D-07..D-13）。

关键约束：契约重放启动真实二进制并加载 `native/GM3000/macos/x86_64/libgm3000.1.0.dylib`（已提交，x86_64）。Linux runner 缺 Linux `.so`，会让 37 个夹具全部漂移，因此全量测试必须跑在 **x86_64 macOS runner**。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-04-07 | CI 在 Linux 跑契约重放导致 37 夹具假失败，门禁失去可信度 | HIGH | `test-full` 固定 x86_64 macOS runner；Linux job 只跑不依赖厂商库的子集 |
| T-04-08 | 门禁只是"存在"但不会阻断，失败被忽略 | HIGH | `gate-selftest` 断言失败测试使门禁非零退出；`docs/CI.md` 列出分支保护清单 |
| T-04-09 | CI 与本地命令不一致，本地绿 CI 红 | MEDIUM | 每个 job 的命令在本地 `04-03-04` 逐一 dry-run |
| T-04-10 | 工具链未固定导致 CI 无代码变更变红 | MEDIUM | 04-02 已加 `rust-toolchain.toml`；job 依赖它 |
</threat_model>

<must_haves>
- `.github/workflows/ci.yml` 在 `pull_request` 与 push 到 `main`、`dev` 时触发
- Jobs：`fmt`、`clippy`、`test`、`test-full`、`windows-i686`、`gate-selftest`
- `clippy` job 使用 `-- -D warnings`
- `test-full` 使用 x86_64 macOS runner（实现时确认标签）
- `gate-selftest` 写入必失败测试并断言 `cargo test` 非零退出，随后清理
- `docs/CI.md` 含分支保护必需设置与本地等价命令
- 所有 job 命令在本地可复现且退出 0（除 self-test 的"预期失败"）
</must_haves>

  <action>
    新建 `.github/workflows/ci.yml`，结构与关键值如下（保持简洁、无第三方 action 除 checkout）：
    ```yaml
    name: CI

    on:
      pull_request:
      push:
        branches: [main, dev]

    permissions:
      contents: read

    concurrency:
      group: ci-${{ github.workflow }}-${{ github.ref }}
      cancel-in-progress: true

    jobs:
      fmt:
        name: Formatting
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          - run: cargo fmt --all -- --check

      clippy:
        name: Clippy
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          - run: cargo clippy --all-targets -- -D warnings

      test:
        name: Hardware-free tests (Linux)
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          - run: cargo test --lib
          - run: cargo test --test provider_invariants --test session_invariants --test classification_invariants --test fixture_oracle
          - run: cargo test --test session_isolation --test session_lifecycle --test transport_limits --test ffi_serialization --test loopback_gate

      test-full:
        name: Full suite incl. contract replay (x86_64 macOS)
        # The replay loads the committed x86_64 vendor dylib; an arm64 runner or a
        # Linux runner cannot satisfy it. Confirm the label when first run.
        runs-on: macos-13
        steps:
          - uses: actions/checkout@v4
          - run: cargo test

      windows-i686:
        name: Windows i686 compile check
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          - run: sudo apt-get update && sudo apt-get install -y mingw-w64
          - run: rustup target add i686-pc-windows-gnu
          - run: cargo check --target i686-pc-windows-gnu

      gate-selftest:
        name: Gate self-test (a failing test must be caught)
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          - name: Prove the test gate fails on a failing test
            run: |
              printf '#[test]\nfn deliberate_failure() { assert!(false); }\n' > tests/ci_selftest.rs
              if cargo test --test ci_selftest; then
                echo "::error::the test gate did not fail on a deliberately failing test"
                rm -f tests/ci_selftest.rs
                exit 1
              fi
              rm -f tests/ci_selftest.rs
              echo "gate is failure-sensitive"
    ```
    说明：
    - GitHub runner 的 rustup 会读取仓库根的 `rust-toolchain.toml` 自动安装 1.93.0 与组件，无需额外 step。
    - `test` 与 `test-full` 的分工见 RESEARCH §3.2；`test-full` 是唯一含 `contract_fixtures` 的权威全量。
    - **实现时确认** `macos-13` 标签可用；若不可用，改用当前可用的 x86_64 macOS 标签（如 `macos-15-intel`），并在 SUMMARY 记录最终取值。
  </action>
