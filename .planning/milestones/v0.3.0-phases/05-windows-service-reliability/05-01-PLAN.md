# Plan 05-01: Honest Startup Reporting, Distinct Exit Codes, and Stage-Aware status

<objective>
让 SCM 在初始化期间看到 `StartPending`、仅在监听器已绑定且配置已解析后看到 `Running`；配置无效时以**分类非零退出码**结束以触发重启；`status` 报告启动阶段（SVC-01/02/05，D-01..D-10）。

实现要点：新增跨平台 `service_state` 模块（状态文件 + 退出码常量），在 `server` 增加 `bind_with_progress`/`StartupError`，重写 `win_service::run_service`，并让 `status` 读取状态文件。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-05-01 | 服务在监听器/配置就绪前报 Running，SCM 与运维被误导 | HIGH | 用 `bind_with_progress` 的进度回调；Running 只在 bind 成功后上报 |
| T-05-02 | 初始化失败以 exit code 0 结束，重启策略不触发 | HIGH | `StartupError` 分类 → `ServiceExitCode::ServiceSpecific(1..4)` |
| T-05-03 | 状态文件含配置值/路径/凭据，泄露敏感信息 | HIGH | 只序列化 `state/stage/code/reason/pid/address/updated`；单测断言无敏感字段 |
| T-05-04 | 状态文件被撕裂读取 | MEDIUM | 临时文件 + rename 原子写 |
| T-05-05 | 把"库加载失败"误判为致命，破坏 Linux CI 的降级启动 | HIGH | D-08/D-09 边界：仅配置无效致命；库加载失败降级并仍报 Running；用单测固定 |
</threat_model>

<must_haves>
- 新增 `src/service_state.rs`（跨平台）：状态枚举、`write_atomic`、`read`、`EXIT_CONFIG/PROVIDER/BIND/SERVE` 常量、无敏感字段
- `server` 提供 `bind_with_progress` 与 `StartupError{Config,Provider,Bind}`；`bind` 委托且行为不变
- `run_service` 顺序为：写 `StartPending(config)` → 进度 `provider`/`bind` → 绑定成功写 `Running(serve)` → `serve`；失败写 `Failed(stage,code,reason)` 并以 `ServiceSpecific(code)` 报 Stopped
- `status` 优先读状态文件并打印阶段；缺文件时回退 SCM-only
- 配置无效（不可解析 / default 别名缺失 / 当前 OS 无路径）致命；库文件缺失/加载失败降级（D-08/D-09）
- `cargo test`、`cargo test --test contract_fixtures` 37/37、`cargo check --target i686-pc-windows-gnu` 全部通过
</must_haves>

    新建 `src/service_state.rs`，仅在任意平台编译（不 `cfg(windows)`）：
    ```rust
    /// Startup phases the service reports. Used both for the status file and for
    /// mapping a failure to a distinct service exit code.
    #[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
    #[serde(rename_all = "snake_case")]
    pub enum StartupStage { Config, Provider, Bind, Serve }

    pub const EXIT_CONFIG: u32 = 1;
    pub const EXIT_PROVIDER: u32 = 2;
    pub const EXIT_BIND: u32 = 3;
    pub const EXIT_SERVE: u32 = 4;

    impl StartupStage {
        pub fn as_str(self) -> &'static str { ... } // "config"|"provider"|"bind"|"serve"
        pub fn exit_code(self) -> u32 { ... }       // 1|2|3|4
    }

    #[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
    #[serde(rename_all = "lowercase", tag = "state")]
    pub enum ServiceState {
        StartPending,
        Running,
        Failed,
        Stopped,
    }

    #[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
    pub struct ServiceStatusFile {
        pub state: ServiceState,
        pub stage: StartupStage,
        #[serde(skip_serializing_if = "Option::is_none")] pub code: Option<u32>,
        #[serde(skip_serializing_if = "Option::is_none")] pub reason: Option<String>,
        #[serde(skip_serializing_if = "Option::is_none")] pub pid: Option<u32>,
        #[serde(skip_serializing_if = "Option::is_none")] pub address: Option<String>,
        #[serde(skip_serializing_if = "Option::is_none")] pub updated: Option<String>,
    }
    ```
    但 `serde` 的 internally-tagged enum 与 struct 组合需简化：**改用一个扁平 struct**，字段为 `state: String`（值 `start_pending|running|failed|stopped`）或一个 `#[serde(rename)]` 枚举字段，避免 tag 复杂度。实现者可用：
    ```rust
    pub struct ServiceStatusFile {
        pub state: String,          // "start_pending" | "running" | "failed" | "stopped"
        pub stage: String,          // StartupStage::as_str
        pub code: Option<u32>,
        pub reason: Option<String>,
        pub pid: Option<u32>,
        pub address: Option<String>,
        pub updated: Option<String>,
    }
    ```
    并提供构造器 `fn pending(stage, pid)`, `fn running(stage, address, pid)`, `fn failed(stage, code, reason, pid)`, `fn stopped()`。
    再提供：
    ```rust
    /// Write atomically: temp file in the same directory, then rename over target.
    pub fn write_atomic(path: &std::path::Path, value: &ServiceStatusFile) -> std::io::Result<()>;
    pub fn read(path: &std::path::Path) -> Option<ServiceStatusFile>;
    ```
    `reason` 必须由调用方传入**短且不含敏感值**的文本；模块 doc 注明"不得写入配置值、库路径、PIN、密钥"。
    在 `src/lib.rs` 增加 `pub mod service_state;`。
    增加 `#[cfg(test)] mod tests`：
    - `round_trip_serializes_and_parses`；
    - `atomic_write_replaces_content_and_leaves_no_tmp`（写两次，第二次覆盖；目录中无 `.tmp` 残留）；
    - `serialized_failed_state_contains_no_config_values`（构造 failed，断言 JSON 不含某个哨兵路径字符串）；
    - `stage_maps_to_distinct_exit_codes`（四个阶段 → 1/2/3/4，互不相同）。
  </action>

    2. 实现 `pub async fn bind_with_progress<F>(opts, factory, on_stage: impl Fn(StartupStage)) -> Result<(BoundServer, TcpListener, PreparedServer), StartupError>`：
       - `on_stage(Config)`；`config::load` 失败 → `StartupError::Config(e.to_string())`；
       - `on_stage(Provider)`；检查默认 provider 在当前 OS **有路径配置**：`crate::config::resolve_lib_path(&config.libs, &config.default, std::env::consts::OS).map_err(|e| StartupError::Provider(e.to_string()))?`；随后 `factory.build(&config)`（库加载失败仍返回 `UnavailableProvider`，**不**视为错误，D-09）；

       - 保留现有日志/错误文本（如 `"failed to bind WebSocket listener on {}: {}"`）。
    3. `pub async fn bind<F>(opts, factory) -> anyhow::Result<...>` 改为调用 `bind_with_progress(opts, factory, |_| {})` 并把 `StartupError` 转成 `anyhow::Error`（`impl Error` 即可），保持既有调用方与测试不变。
    4. 抽取工作目录回退为 `pub fn prepare_working_directory(config_path: &str)`，`run_server` 调用它。
    5. 增加 `#[cfg(test)] mod tests`（用 `UnavailableProvider` 的测试 factory，无需厂商库）：

       - `missing_os_path_is_a_provider_error`（YAML 中 default 只有 windows 路径，OS=当前 → `StartupError::Provider`）；
       - `unparseable_config_is_a_config_error`；
       - `bind_failure_is_a_bind_error`（先 `TcpListener::bind("127.0.0.1:0")` 占用端口，再用该端口调用 → `StartupError::Bind`）；

  <action>
    1. 新增 `fn state_file_path() -> PathBuf`（exe 同目录 `service-state.json`）。
    2. 重写 `run_service()`：
       - 注册 handler 后**先**上报 `StartPending`（`checkpoint: 0`, `wait_hint: 10s`），并写 `ServiceStatusFile::pending(Config, pid)`。
       - 调用 `crate::server::prepare_working_directory(...)`（或等价）与 `bind_with_progress`，回调按阶段写 `pending(stage)` 并**递增 checkpoint** 再次 `set_service_status(StartPending{checkpoint, wait_hint})`。
       - `bind` 成功 → 取 `bound.ws_addr`，上报 `Running`（`checkpoint: 0`），写 `running(Serve, addr, pid)`。
       - 通过 `installed_session_builder()` 构建 sessions（与 `run_server` 一致），再调用 `crate::server::serve(listener, prepared, bound, sessions, Some(stop_rx))`。
       - 失败：`StartupError` → `code = e.exit_code()`，写 `failed(e.stage(), code, reason, pid)`，上报 `Stopped` 且 `exit_code = ServiceExitCode::ServiceSpecific(code)`，返回 Err。
       - `serve` 正常返回 → 写 `stopped()`，上报 Stopped（exit code 0）。
       - 运行期错误（`serve` 返回 Err）→ code `EXIT_SERVE`，同上。
       - `reason` 只写短文本（如阶段名 + 错误首行），**不得**包含库路径或配置值；必要时截断到 ~200 字符。
    3. `status()`：读取 `state_file_path()`；存在则打印 `state`、`stage`、`code`、`address`、`updated`（例如 `Service 'X': Running (stage=serve, address=127.0.0.1:9001)`；失败时 `Failed (stage=bind, code=3)`）；随后仍打印 SCM 状态与 exe 路径。文件不存在时保持现有输出。
    4. 保持 `install`/`uninstall`/`start`/`stop` 与 `delete_if_present`/`wait_until_removed` 行为不变（05-02 再动安装器）。
    5. 若 `service_state` 的常量与 `StartupError::exit_code` 重复，统一引用 `crate::service_state::{EXIT_CONFIG, EXIT_PROVIDER, EXIT_BIND, EXIT_SERVE}`。
  </action>
