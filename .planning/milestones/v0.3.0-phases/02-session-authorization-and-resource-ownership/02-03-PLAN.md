# Plan 02-03: Opaque, Session-Owned Resource Handles

<objective>
消除"客户端可控制原生句柄"这一缺陷：客户端只接触服务端签发的 `dev-N`/`app-N`/`cnt-N`/`hsh-N`，句柄表的键限定在会话内，会话结束时全部资源确定性释放。

本计划同时收口研究确认的 V-1（被放弃的 digest 句柄会永久泄漏设备句柄）与 V-2（digest 路径按次加载库）——它们都在这一批分支上。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-02-05 | 客户端提供的整数被转换回原生指针交给厂商库 | HIGH | 句柄解析只接受会话表内的字符串键；解析失败返回 `-11`，**绝不**把输入转换成指针。测试断言 `DisConnectDev`/`GenerateRandom` 收到整数或未知字符串时返回 `-11` 且进程存活 |
| T-02-13 | 句柄表跨会话共享，使 A 的句柄在 B 中可用 | HIGH | 表是 `SessionState` 的字段（会话独占）；测试断言会话 B 使用 A 的句柄被拒（RES-05） |
| T-02-02 | 会话结束只注销注册表而不释放原生句柄 → 设备句柄泄漏（V-1 的重演） | HIGH | 句柄表由 `SessionGuard` 按值持有，其 `Drop` 逐个 drop 守卫；测试断言断连后 `CloseDevice`/`CloseDigest` 被记录 |
| T-02-14 | 句柄格式泄漏给客户端（前缀暴露内部结构） | MEDIUM | 句柄值可含前缀（客户端视为不透明串），但错误消息**不得**回显前缀或输入值（D-14） |
| T-02-07 | 迁移这批分支时夹带行为变更 → 回归不可归因 | HIGH | digest 拒绝消息逐字保留（契约边界）；每个分支迁移后由其夹具单独验证 |

**Security constraint:** 本计划不得让任何原生指针类型出现在 `src/session/` 中；守卫继续以整数存储句柄（D-22）。
</threat_model>

<must_haves>
- 句柄形态为 `dev-N`/`app-N`/`cnt-N`/`hsh-N`，且是会话内唯一的
- `DisConnectDev`、`GenerateRandom` 收到客户端伪造的整数时返回 `-11`，进程不崩溃
- 未知、过期、类型错误的句柄各自被拒，错误消息不含输入值或前缀（D-14）
- 断连（含异常断开）后所有句柄释放（`CloseDevice`/`CloseApplication`/`CloseContainer`/`CloseDigest` 被记录）
- digest 的拒绝契约逐字保留：`-11` + `"Invalid or expired hash handle"`
- `src/session/` 不出现原生指针类型；`unsafe impl` 数量不变
</must_haves>

    1. 在 `src/session/mod.rs` 增加 `pub mod handles;`，并给 `SessionState` 增加字段 `handles: HandleTable`。
    2. 创建 `src/session/handles.rs`：
       ```rust
       /// How a handle request failed. Never carries the offending value: the
       /// client must not learn internal structure (D-14).
       #[derive(Debug, Clone, Copy, PartialEq, Eq)]
       pub enum HandleError {
           Unknown,
           WrongKind,
       }

       /// Resource kinds a session can own.
       #[derive(Debug, Clone, Copy, PartialEq, Eq)]
       pub enum ResourceKind { Device, Application, Container, Digest }

       impl ResourceKind {
           fn prefix(self) -> &'static str { /* dev | app | cnt | hsh */ }
       }

       /// One owned native resource, or a handle to one.
       ///
       /// No native pointer type appears here (D-22): the guards keep their own
       /// handles as integers and release them in `Drop`.
       pub enum SessionResource {
           Device(Box<dyn crate::provider::DeviceGuard>),
       }

       /// Handles issued by one session, keyed by their opaque identifier.
       ///
       /// Owned by value inside `SessionState`, which the session reaches through
       /// `&mut self`, so no lock is needed (G-1). Dropping the table drops every
       /// guard, which is what makes release-on-disconnect deterministic (RES-03).
       #[derive(Debug, Default)]
       pub struct HandleTable {
           next_id: u64,
           device: std::collections::HashMap<String, Box<dyn crate::provider::DeviceGuard>>,
           // application / container / digest maps are added by the tasks below
       }

       impl HandleTable {
           pub fn issue_device(&mut self, guard: Box<dyn crate::provider::DeviceGuard>) -> String
           /// Look up a device handle. `expected` is checked against the prefix so
           /// a container id can never be used where a device id is expected.
           pub fn device(&mut self, handle: &str) -> Result<&mut Box<dyn crate::provider::DeviceGuard>, HandleError>
           pub fn remove_device(&mut self, handle: &str) -> Result<Box<dyn crate::provider::DeviceGuard>, HandleError>
           pub fn len(&self) -> usize
           pub fn is_empty(&self) -> bool
           fn parse(&self, handle: &str, expected: ResourceKind) -> Result<&str, HandleError>
       }
       ```
       `parse` 的语义：不含 `-`、前缀未知、或前缀与 `expected` 不符 → `WrongKind`；前缀正确但表中无该键 → `Unknown`。**不得**返回输入值本身。
    3. 本任务只实现 **device** 子表；application/container/digest 由后续任务补上，接口命名保持一致（`issue_application`/`application`/... 等）。
    4. 添加 `#[cfg(test)] mod tests`，覆盖：
       - `issue_device` 返回 `dev-1`，第二次返回 `dev-2`
       - 未知键 `dev-99` → `Unknown`
       - 把 `cnt-1` 交给 `device()` → `WrongKind`
       - 无前缀的字符串、空字符串、以及**纯数字**（旧客户端会把指针十进制串发回来）→ `WrongKind`
       - `remove_device` 后同一键再查 → `Unknown`，且 `len()` 减一
       - drop 整个 `HandleTable` 不 panic
  </action>

    - `.planning/phases/02-session-authorization-and-resource-ownership/02-RESEARCH.md` §V-1（被放弃的句柄永久泄漏）、§V-2（6 个分支按次加载库）、§Contract Boundary
    - `src/session/handles.rs` — `issue_digest`/`digest`/`remove_digest`
  </read_first>
  <action>
    1. `DigestInit`：改为 `device_guard.begin_digest(alg_id, id_bytes)`（Phase 1 已把该方法放到 `DeviceGuard` trait 上），把返回的 `Box<dyn DigestGuard>` 存入会话句柄表，响应返回 `{"handle": "hsh-N"}`。
       - **不再**使用 `format!("hash_{}", id)` 作为键；`hash_handles` 进程级 map 整体删除。
       - **不再**在分支内 `Library::new`（消除 V-2）：guard 由 provider 创建，provider 持有唯一库实例。
    2. `DigestUpdate`/`DigestFinal`/`CloseHash`：
       - 从会话句柄表解析 `hsh-N`。
       - **解析失败时必须返回 `-11` 且消息逐字为 `"Invalid or expired hash handle"`** —— 这是夹具冻结的契约（Contract Boundary）。英文与中文分支都保持该英文消息（现有实现对该错误只有英文消息）。
       - `DigestUpdate` 成功路径调用 `guard.update(data)`；`DigestFinal` 调用 `guard.finalize()` 后**从表中移除**（drop 释放）；`CloseHash` 从表中移除并返回 `true`。
       - 三个分支**都不得**再出现 `Library::new`。
    3. 测试（加入 `tests/session_isolation.rs`）：
       - `digest_handle_is_released_on_disconnect`：`DigestInit` 成功后断连，断言 fake 的 `call_count(CloseDigest) == 1` 且 `CloseDevice == 1`（**这是 V-1 的回归测试；迁移前必然失败**）
       - `digest_handle_from_another_session_is_rejected`（RES-05）
       - `unknown_digest_handle_message_is_frozen`：断言返回的 message 字符串与夹具中的完全相同
  </action>
