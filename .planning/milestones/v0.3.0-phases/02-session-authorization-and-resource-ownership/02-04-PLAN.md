# Plan 02-04: Protocol Extraction, Domain Migration, and Release-on-Error

<objective>
完成本阶段的结构收口：把协议层抽到 `protocol/`，把剩余 12 个安全相关分支迁入 `domain/`，并确保**原生错误路径同样释放资源**（RES-04）——这是研究中唯一无法靠现有测试覆盖、只能靠 fake 注入失败来验证的要求。

同时把 `main.rs` 收敛为组合根 + `Session` 实现 + 14 个未迁移分支（D-17/D-21）。
</objective>

<threat_model>
**ASVS Level:** 1 · **Block on:** high

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-02-06 | 迁移时只处理成功路径，错误路径仍漏释放资源 → RES-04 失效 | HIGH | 每个迁移的领域函数用守卫（RAII）；测试用 `fail_next` 在**每一步**注入失败并断言 `Close*` 被记录。这是本计划的验收核心 |
| T-02-07 | 搬运中夹带行为变更（错误消息、边界处理），使回归不可归因 | HIGH | 每个分支迁移后由其夹具单独验证；`cargo test --test contract_fixtures` 必须保持 37/37 |
| T-02-15 | 类型化参数提取改变了某分支的参数校验行为（错误码从 -2 变为其他） | MEDIUM | 提取辅助的错误码与消息必须与现有逐分支实现一致；对参数缺失的夹具逐条比对 |
| T-02-16 | `&mut` 借用被参数提取打断，迫使引入锁或克隆守卫 | MEDIUM | 提取辅助一律先于资源解析调用，把解析结果存入局部变量；守卫在借用期间不被重新借用 |

**Security constraint:** 未迁移的 14 个分支（D-17）**不得**出现行为变更；它们可以继续直连 `SkfApi`，但不得再新增 `ctx.pins` 读取。
</threat_model>

<must_haves>
- `protocol/` 提供类型化参数提取，参数缺失的错误码与消息与迁移前一致
- 12 个分支迁入 `domain/`，`main.rs` 仅保留组合根、`Session` 实现与 14 个未迁移分支
- 每个领域函数的原生错误路径都释放资源（守卫 RAII）
- `cargo test --test contract_fixtures` 37/37 匹配
- `cargo check --target i686-pc-windows-gnu` 通过
- 全 crate 的 `unsafe impl` 仍恰好各一处
</must_haves>

    2. 创建 `src/protocol/params.rs`，提供类型化提取，**错误码与消息与现状一致**：
       ```rust
       /// Positional parameter access with the pre-refactor error shape preserved.
       ///
       /// Every helper returns `Err(RpcResponse)` built exactly as the branch-level
       /// code did, so migrating a branch cannot change its validation contract.
       pub struct Params<'a> { values: &'a [serde_json::Value], id: Option<serde_json::Value> }

       impl<'a> Params<'a> {
           pub fn new(values: &'a [serde_json::Value], id: Option<serde_json::Value>) -> Self
           /// Required string; missing/wrong type yields -2 with the given message.
           pub fn required_str(&self, index: usize, message: &str) -> Result<&'a str, RpcResponse>
           /// Optional string with a default (matches `.and_then(as_str).unwrap_or(default)`).
           pub fn optional_str(&self, index: usize, default: &'a str) -> &'a str
           pub fn required_u64(&self, index: usize, message: &str) -> Result<u64, RpcResponse>
           pub fn optional_u64(&self, index: usize, default: u64) -> u64
           pub fn optional_bool(&self, index: usize, default: bool) -> bool
           /// Base64 decode; failure yields -2 "Invalid base64 data: {e}" to match
           /// the existing digest/encrypt paths.
           pub fn required_base64(&self, index: usize, message: &str) -> Result<Vec<u8>, RpcResponse>
           pub fn len(&self) -> usize
           pub fn is_empty(&self) -> bool
       }
       ```
       **关键约束：** `required_str` 的错误码必须是 `-2`，消息由调用方传入（各分支的既有消息不同，例如 `"Missing deviceName param"`、`"Missing param"`）。不得统一措辞。
    3. 在 `src/protocol/params.rs` 添加 `#[cfg(test)] mod tests`，覆盖每个辅助的成功与失败路径，并断言错误码为 `-2`、`id` 被正确带回。
    4. `main.rs` 改为 `use skf_service::protocol::{Language, RpcRequest, RpcResponse};` 并删除本地定义。此任务**不**改动任何分支逻辑。
  </action>
