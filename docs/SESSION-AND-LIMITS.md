# Session, Authorization, and Limits / 会话、授权与限制

## 中文

### 会话与授权模型

- 每个 WebSocket 连接拥有独立的会话；会话 ID 由 `OsRng` 生成、32 位十六进制，**不下发**给客户端，也不支持重连认领。
- 授权表示为 `(provider, device, application) -> expires_at`。TTL 来自环境变量 `SKF_AUTH_TTL_SECONDS`，默认 **600 秒**；`0` 或非法值回落到默认值。
- `CheckPIN` 成功后只记录一个 deadline。**不保留任何可恢复的 PIN 副本**（`Grant` 只含 `Instant`）。
- 授权在三条路径被清除：连接断开、TTL 到期、以及某次操作发现设备不可用（检测发生在下一次使用，而非即时广播）。
- 原生资源（设备、应用、容器、摘要）由服务端签发的不透明句柄表示：`dev-N`、`app-N`、`cnt-N`、`hsh-N`。句柄属于会话；未知、过期或类型错误的句柄返回 `-11`。
- 资源以守卫（RAII）持有：成功、原生错误、断连、会话结束都会确定性释放。

### 限制

| 项 | 值 |
|----|----|
| WebSocket 消息 / 单帧 | 1 MiB |
| 单次操作载荷（解码前校验） | 256 KiB |
| 并发连接 | 64（超限立即拒绝） |
| 非 `WaitForDevEvent` 请求超时 | 30 秒（`SKF_FFI_TIMEOUT_SECONDS` 可覆盖） |
| 原生调用串行化 | 每 provider 库一把全局锁 |
| 非回环绑定 | 默认拒绝，需 `allow_remote: true` 或 `SKF_ALLOW_REMOTE=1` |

超时只让**调用方**停止等待，不会取消已在执行的厂商调用。

### 受限方法

`IssueCertificate` 与 `Transmit` 始终存在。默认可用；设置 `SKF_RESTRICT_LEGACY=1`
后返回文档化错误 `-100`。需要限制它们的部署应在迁移调用方处理 `-100` 后再启用。

### 协议版本

请求可带可选 `apiVersion`；未发送即视为版本 1（v0.2.0 客户端）。`GetProtocolVersion`
返回 `{"min":1,"current":1,"service":"0.3.0"}`。请求高于当前版本返回 `-1` 与文档化消息。

## English

### Session and authorization model

- Every WebSocket connection owns its own session. The session id is generated by
  `OsRng` (32 lowercase hex characters), is **never sent** to the client, and cannot
  be claimed by reconnecting.
- Authorization is `(provider, device, application) -> expires_at`. The TTL comes
  from `SKF_AUTH_TTL_SECONDS`, default **600 s**; `0` or an invalid value falls back
  to the default.
- A successful `CheckPIN` records only a deadline. **No recoverable PIN copy is
  retained** (`Grant` holds only an `Instant`).
- Authorization is cleared on three paths: disconnect, TTL expiry, and an operation
  that finds the device unavailable (detected on next use, not by an instantaneous
  broadcast).
- Native resources (device, application, container, digest) are named by
  server-issued opaque handles: `dev-N`, `app-N`, `cnt-N`, `hsh-N`. Handles belong
  to one session; unknown, expired, or wrong-kind handles return `-11`.
- Resources are held as guards (RAII): success, native error, disconnect, and
  session end all release them deterministically.

### Limits

| Item | Value |
|------|-------|
| WebSocket message / frame | 1 MiB |
| Operation payload (checked before decoding) | 256 KiB |
| Concurrent connections | 64 (excess refused) |
| Non-`WaitForDevEvent` request timeout | 30 s (`SKF_FFI_TIMEOUT_SECONDS` overrides) |
| Native-call serialization | one global lock per provider library |
| Non-loopback binding | refused by default; needs `allow_remote: true` or `SKF_ALLOW_REMOTE=1` |

A timeout stops the **caller** waiting; it does not cancel a vendor call already
running.

### Restricted methods

`IssueCertificate` and `Transmit` are always present. They work by default; with
`SKF_RESTRICT_LEGACY=1` they return the documented error `-100`. Deployments that
restrict them should update callers to handle `-100` first.

### Protocol version

A request may carry an optional `apiVersion`; omitting it means version 1 (a
v0.2.0 client). `GetProtocolVersion` returns
`{"min":1,"current":1,"service":"0.3.0"}`. Requesting a version above the current
one returns `-1` with a documented message.
